## 클라이맥스 설계 — 02-02 OTA에서 02-07 스물여덟째 아침까지

### 원칙 (작성자와 검토자가 같이 지킴)

1. **화면이 클라이맥스다.** 문장은 짧은 관찰로 둔다. '드디어'·'감동'·'눈물'·'마지막 인사' 같은 감상어, 카운트다운 스티커, 느낌표를 쓰지 않는다.
2. **끝맺음으로 말하지 않는다.** 28밤 뒤 몽망이가 곁에 남는지 떠나는지는 팀 결정 전이다(D-26, risk-check 1-6). '이별·작별·마지막 밤'을 훅으로 쓰지 않고, 앱이 28밤 뒤에 보이는 화면(화첩 선반·새 방울 등)은 찍지도 올리지도 않는다.
3. **확정되지 않은 것은 보이지 않는다.** 낙관은 앱이 찍는 **기본 면('몽')** 그대로 둔다. 개발자는 인장을 새기지 않는다(I-013 V39는 자를 수 있는 항목 — 1.0 조건부, 홍보 금지). 22번째 아침(02-01)에 앱이 '돌'을 굴려 오는 연출이 나와도 녹화·게시하지 않는다. 합작·실제 걸음도 말하지 않는다.
4. **스물여덟 낱말이 회수된다.** 1주차부터 쌓은 낱말 목록이 02-07 답글 한 장(한 줄에 일곱 낱말 × 넷)과 실물 한지 한 장(P13)으로 모인다. 그날 새로 말하는 것은 '봄' 하나다.
5. **같은 날, 같은 순서.** 모든 채널이 02-07 아침 한 시간 안에 같은 사실(봄 → 다 자란 모습 → 낙관)을 같은 순서로 말한다.
