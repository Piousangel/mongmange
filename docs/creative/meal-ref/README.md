## 1. 생성 계획

```
node scripts/gemini-meal-ref.mjs --env .env.local          # 9품목 × (flash 4 + pro 2) = 54장
node scripts/gemini-meal-ref.mjs --env .env.local --only dewdrop,inkstone-clear   # 일부만
```

- 모델: `gemini-3.1-flash-image` 4안(`-f1~f4`), `gemini-3-pro-image` 2안(`-p1~p2`). 요청 1:1·2K(2048px) → 저장소에는 1536px JPG(품질 90).
- 키는 스크립트 안에서만 읽고 출력·파일에 남기지 않는다(오류 본문도 키를 가린다).
- 프롬프트 원문은 생성할 때 `prompts.json`에 장마다(모델·날짜·크기·문장) 남는다. 품목별 문장은 `scripts/gemini-meal-ref.mjs`의 `ITEMS`, 공통 조건은 `COMMON`.

## 2. 판정 절차 (생성 뒤, 작성자 ≠ 리뷰어)
1. **QA-3 섭식 안전 표시(먼저, 후보마다)**: 위험 있음 / 없음 + 한 줄. 볼 것 — 수북함·넘침·여러 개(폭식 연상), 윤기·김(먹음직), '빈 그릇 = 칭찬' 짝(연지 '비어 있음'이 꾸중·결핍으로 읽히는지), 숟갈 수·분량 눈금, 몸·생명체 흔적(R8·R9 몸 크기 연상 0). 위험 있음은 판정 후보에서 뺀다.
2. **블라인드 아트 판정**: 작성자가 아닌 서브에이전트에 파일 이름(모델 표시 지움)만 섞어 넘긴다. 품목마다 1안 + 통과 / 다듬기 / 탈락 + 한 줄 이유. 기준: 64pt 판독, 먹 한 색(송화만 예외), 세트 통일감(같은 붓·같은 먹색, C14b 3-3 '콜라주' 위험), 연지 3상태는 같은 벼루로 이어 보이는지.
3. **비교 시트**: 고른 안을 64pt·128pt·다크(`bg` 밤 `#141A2C`) 바탕에 놓은 `sheet.png`. 다크 칸은 아래 3절 ②의 알파 손질판으로 놓는다(원본 곱하기 합성은 밤에 깨짐 — C14b 3-3).

## 3. 다음 단계 — 손질 파이프라인과 V30 아이콘 6개로 가는 길
- **손질(C14b `motif-raster.mjs`와 같은 순서)**: ① 가장자리 중앙값 = 종이 밝기로 배경 제거 ② 밝기 → 알파, 먹 한 색(색은 앱 토큰 `stroke-ink`·밤 `body`로 입힘) ③ 알파 0.06 아래 0으로 종이 결 지우기(종이 결은 앱 공통 한 장) ④ 최대 농도 0.72(몽망이 몸보다 옅게 — 아트 바이블 7-6 2항) ⑤ 경계 상자 자르기 + 긴 변 256px WebP(아이콘은 시트 안 36pt·3x = 108px이 상한이라 256이면 충분, 장당 30KB 목표). 송화 노랑은 알파 채널과 따로 둔 '색 점' 한 겹으로 분리하거나, 모자라면 앱에서 점 3개를 코드로 얹는다.
- **연지 상태 3**: 3D 벼루(V12b)에 굽는 쪽이 정본이다(care-rituals 3-4 L8). 래스터는 그 굽기의 **목표 이미지**로 쓰고, 2D 시트 아이콘에는 '비어 있음'을 쓰지 않는다(빈 상태를 보이는 것 자체가 결핍 신호 — 연지는 벼루 그림 안에서만 바뀐다).
- **V30 아이콘 6개(낮·밤)**: 통과 6안 손질 → `apps/mobile/assets/meal/<id>.webp` → 64pt 축소에서 같은 품목끼리 헷갈리는 쌍 0(특히 `clear-ink`·`dew-ink`는 농도만 다르니 고리 유무로 갈라야 한다) → 아트 리뷰(작성자 ≠ 리뷰어) → QA-3 관문 → license-ledger 1절에 `출시 사용: 앱` 행(모델·프롬프트 요약·날짜·손질 내용) 추가. 다듬기 판정 품목은 `--only <품목> --force`로 다시 뽑거나 프롬프트를 고친다.
- 라이선스: 지금은 생성물이 없어 원장에 적을 장이 없다. 생성하면 1절에 장마다 '탐색 — 앱 사용 전 손질·리뷰 필요'로 적는다.
