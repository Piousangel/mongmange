## 1. 생성

```
node scripts/gemini-meal-ref.mjs --env .env.local --flash 3 --pro 1   # 이번 실행: 9품목 × 4안 = 36장
```

- **바뀐 점(코디네이터 지시, 비용 절약)**: 처음 계획은 품목마다 flash 4안 + pro 2안이었다. 이번에는 **flash 3안(`-f1~f3`) + pro 1안(`-p1`)**으로 줄였다. 스크립트 기본값(4·2)은 그대로 두고 인자로 바꿨다.
- 모델: `gemini-3.1-flash-image`, `gemini-3-pro-image`. 요청은 1:1·2K(2048px)였고, 저장소에는 1536px JPG(품질 90)로 둔다. 36장의 합계는 16MB다.
- 키는 스크립트 안에서만 읽는다. 출력과 파일에 키가 남지 않았는지 grep으로 확인했다.

## 2. 판정 (작성자 ≠ 리뷰어, 블라인드)

**방법**
- 리뷰어는 서로 독립된 서브에이전트 2명이다(R1·R2). 둘 다 작성에 참여하지 않았다.
- 품목마다 4안을 무작위로 A~D로 바꾼 시트를 넘겼다. 시트에는 원본, 128pt, 64pt, 밤 바탕 64pt가 있다. 모델·파일 이름·작성 의도는 주지 않았다.
- 정답표는 `picks.json`과 아래 표의 '파일' 칸이다.

**수렴 규칙(꿈 그림 때 정한 것)**
- **안전 지적은 1명만 짚어도 고친다.**
- 나머지 지적은 두 사람이 **반복한 것만** 고친다.
- 한 사람만 낸 아트 지적은 '참고'로만 적는다.

### 2-1. QA-3 섭식 안전 표시 (판정 전, 36안 모두)
위험 표시가 있는 안은 판정 후보에서 뺐다. 표시된 안은 36안 중 10안이다. 괄호는 지적한 리뷰어다.

| 품목 | 위험 표시된 안 | 이유 |
|---|---|---|
| 맑은 먹 · 송화 먹 · 연지 한 숟갈 | 없음 | — |
| 이슬 먹 | `f3`(R1·R2) | 숟갈 안의 짙은 동심원이 눈동자로 읽힌다(얼굴 흔적) |
| 이슬 먹 | `f2`(R1) | 숟갈이 아니라 공기라서 한 숟갈보다 많은 분량으로 읽힌다 |
| 무늬 먹 조각 | `f3`(R1·R2) | 흰 하이라이트 윤기, 부푼 쿠션·봉봉 모양(먹음직·부풂 연상) |
| 무늬 먹 조각 | `p1`(R2) | 크고 둥근 판이 파이 한 판(여러 인분)으로 읽힌다 |
| 늘인 먹 한 가락 | `p1`(R2) | 굵은 머리 + 가는 꼬리가 뱀·올챙이(생명체)로 읽힌다 |
| 이슬 한 방울 | `p1`(R1·R2) | 짙은 테에 흰 반사점이 있어 눈알로 읽힌다 |
| 연지 비어 있음 | `f1`(R1·R2) | 귀퉁이가 깨지고 연지 턱이 없어 버려진 벼루·결핍으로 읽힌다 |
| 연지 비어 있음 | `p1`(R2) | 연지 안 마른 얼룩이 방치·굶김 흔적으로 읽힌다 |
| 연지 맑은 먹 | `f2`(R1·R2) | 검고 반짝이는 공이 눈·렌즈로 읽힌다 |
| 연지 맑은 먹 | `f1`(R1) | 연당 전체에 먹이 차 있어 많은 분량으로 읽힌다 |

두 리뷰어가 반복한 위험은 **'둥근 형태 + 동심원 + 점 반사광' = 눈**이다. 이것을 세트 규칙 S1로 올린다(2-3절).

### 2-3. 세트 규칙 (두 리뷰어가 반복했거나 안전 지적인 것)
- **S1(안전)**: 둥근 형태 안에 동심원과 점 반사광을 함께 쓰지 않는다. 눈으로 읽힌다.
- **S2(반복)**: 종이가 제각각이다(흰 액자, 비네팅, 누런 톤). 손질에서 배경을 모두 지우고 앱 한지 한 장으로 통일한다.
- **S3(반복)**: 밤 바탕 알파본에서 숟갈 3종과 물방울은 거의 사라지고, 다식만 흰 덩어리로 튄다. 9품목에 밤 전용 규칙 하나를 똑같이 적용한다(4절 ③).
- **S4(반복)**: 무게가 둘로 갈린다. 다식·먹 한 가락은 굵고 짙고, 숟갈·벼루는 가는 선이다. 간식의 최대 먹 농도를 숟갈 외곽선 농도에 맞춘다.
- **S5(반복)**: 밥 3종은 **같은 숟갈 한 장에 내용물만 바꾼다.** 구별은 내용물로만 한다(맑은 먹 = 중간 회색, 이슬 = 거의 한지색 + 고리 하나, 송화 = 큰 노란 점 3개).
- 참고(R2만): 벼루가 64pt 세로 직사각형이라 스마트폰처럼 읽힐 여지가 있다. 가장자리 붓질을 불규칙하게 한다. 반복되지 않아 고칠 목록에는 넣지 않았다.

## 3. 비교 시트
- 시트: **`sheet.png`**. 9품목의 고른 안을 원본 축소, 128pt, 64pt, 다크 128pt, 다크 64pt(밤 `bg` #141A2C)로 나란히 놓았다.
- 다시 만들기: `node scripts/meal-ref-sheet.mjs picks docs/creative/meal-ref/picks.json`
- 다크 칸은 곱하기 합성이 아니다. 손질 1차로 뽑은 알파를 밤 글자색 `#E9E2D2`로 칠했다. 순서: 테두리 중앙값 = 종이, 가장 짙은 0.5% = 먹, 밝기를 알파로, 0.06 미만은 0, 최대 0.72.
- 그래서 밤 칸에서는 먹 고임이 **밝게 반전된다.** 송화 노랑도 알파에서 사라진다. 이 둘은 4절 ③에서 정한다.
- 블라인드용 품목별 A~D 시트는 커밋하지 않고 스크래치에만 두었다. `scripts/meal-ref-sheet.mjs blind <폴더> <매핑 JSON>`으로 다시 만들 수 있다.

## 4. 다음 단계 — 손질 파이프라인과 V30 아이콘 6개로 가는 길

1. **다듬기 6품목 다시 뽑기**
   - 2-2절 '고칠 점'을 `ITEMS` 문장에 반영한다.
   - 실행: `--only <품목> --flash 3 --pro 1 --force`
   - 먹 한 가락은 네 안이 모두 글자로 읽혔다. 프롬프트를 바꾸는 것이 먼저다.
2. **세트 맞추기(S5)**
   - 밥 3종은 `clear-ink-p1`의 숟갈을 틀로 쓰고 내용물 한 겹만 바꾼다(Gemini 이미지 편집 요청 또는 손질 단계의 마스크 합성).
   - 연지 3상태도 `inkstone-empty-f2`의 벼루 틀 하나에 연지 안 한 겹만 바꾼다.
3. **손질(C14b `scripts/motif-raster.mjs`와 같은 순서, 새 `scripts/meal-raster.mjs`)**
   - ① 배경 제거: 테두리 중앙값 = 종이
   - ② 밝기를 알파로 바꿔 먹 한 색으로. 색은 앱이 입힌다. 낮은 `stroke-ink`, 밤은 **선만 `#E9E2D2`, 먹 고임은 밤 `stroke-ink` #59585A**(S3, 반전 방지).
   - ③ 알파 0.06 미만은 0(종이 결은 앱 공통 한 장)
   - ④ 최대 농도 0.72. 송화 노랑은 알파와 따로 '색 점' 한 겹으로 분리한다. 부족하면 앱이 점 3개를 코드로 얹는다.
   - ⑤ 경계 상자로 자르고 긴 변 256px WebP. 시트 아이콘 상한은 36pt·3x = 108px이다. 장당 30KB 목표.
   - ⑥ 64pt 판독 시험: 밥끼리, 간식끼리 헷갈리는 쌍 0
4. **연지 3상태**
   - 정본은 V12b 3D 벼루에 굽는 쪽이다(care-rituals 3-4 L8). 래스터 3장은 그 굽기의 **목표 이미지**로 쓴다.
   - '비어 있음'은 시트 아이콘으로 쓰지 않는다. 벼루 그림 안에서만 보인다.
5. **V30 아이콘 6개(낮·밤)**
   - 순서: 통과 6안 손질 → `apps/mobile/assets/meal/<id>.webp` → 아트 재리뷰(작성자 ≠ 리뷰어) → QA-3 관문 → license-ledger 1-1 같은 손질본 행 추가(`출시 사용: 앱`, 모델·프롬프트 요약·날짜·손질 내용).
   - 앱 코드 연결은 V28 시트가 나온 뒤에 한다.

- 라이선스: 36장 모두 license-ledger 1절에 '탐색 — 앱 사용 전 손질·리뷰 필요'로 적었다.
