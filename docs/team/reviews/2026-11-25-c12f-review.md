## 2. 항목별 판정

### 2-1. 인가 — 통과
- 경로는 기존 `AuthGuard`를 그대로 탄다(`@AllowUnlinked` 없음). 서명·iss·aud·exp를 검증한 토큰의 `sub`로 `user_auth`를 찾고, 행이 없으면 401 `no_account`, revoked면 410 `moved`다. 모든 조회는 가드가 돌려준 `userId` 하나(`linkedUser(a)`)에 묶이고, 세이브·이력은 그 사용자 creature의 `c.id`에 묶인다. 요청에서 받는 id 인자는 0개다. 남의 sub를 넣은 위조 토큰은 DB를 보기 전에 401 `unauthorized`로 떨어진다.
- 옮겨 간 계정: 옛 sub는 410이고, 새 기기는 같은 user로 200(`logins 1 · movedLogins 1`)이다. 시험이 있다.
- 지운 계정: users 행이 없으므로 가드에서 401 `no_account`다. 흔적을 따로 두지 않는다. 시험이 있다.
- 동시 삭제 중 조회: 가드와 첫 조회 사이에 지워지면 `if (!acc) throw noAccount()`가 받는다. 다만 네 조회가 한 트랜잭션(스냅숏) 안에 있지 않다. 그래서 첫 조회 뒤에 지워지면 '계정은 있는데 creature·save는 null' 같은 섞인 응답이 나갈 수 있다. 이것도 **본인 것뿐**이고 creature id(uuid)는 재사용되지 않아 남의 데이터로 번지지 않는다(낮음 L2).
- 사용자당 30/시간은 전역 IP 분당 한도와 별개다. 키는 userId이며 메모리에만 있고 로그에 싣지 않는다. 같은 방식(`save_put`·`page_put`)이 이미 쓰이고 있다.

### 2-2. 응답 누출 — 통과(권고 있음)
- 응답 칸: 계정 메타 7, creature(code·만든 때·글귀 있음 여부·링크 5), save(rev·두 시각·날·획 수·검증·bytes), 이력(사유·두 시각·날·획 수·bytes). 이름(`public_pages.meta.name`)·글귀 해시·sub·userId·sha·내부 id·public_id·store_key·path_prefix는 **조회조차 하지 않는다**. 본문은 `octet_length`로 크기만 잰다.
- strict 스키마가 서버에서 적용되는가: **런타임에는 적용되지 않는다.** 서버는 객체를 그대로 직렬화한다. 대신 두 겹으로 막는다. ① 반환이 객체 리터럴이라 TS 초과 속성 검사가 잡는다(변이 S5b, `error TS2353`). ② `c12f.db.test.ts`가 실제 응답을 `myDataSchema.safeParse`(strict)로 검사한다(S5). 그래도 스프레드(`...row`)로 칸을 넣으면 ①을 빠져나가고, ②는 시험이 덮는 갈래에서만 잡는다 → 낮음 L1(직렬화 전에 `myDataSchema.parse`).
- 시각 정밀도: 시각은 모두 ms 단위 ISO로 나간다. 화면은 '마지막으로 맡긴 때'만 분까지 쓰고, 나머지는 날짜만 쓴다. 본인 열람이라 법적 문제는 아니지만, 최소화 원칙으로 보면 서버에서 날짜·분 단위로 잘라도 화면은 그대로다 → 낮음 L6(선택).

### 2-3. 로그·감사 — 통과
- 감사는 요청 로그 한 줄이다(`route` 템플릿 `/api/v1/me/data`·상태). 서비스 안에는 로그 호출이 0개다. 시험이 실제 로그 스트림을 받아 sub·code·userId·token·IP·이름이 0건임을 단언한다.
- 레이트리밋 오류 본문은 `{code:'rate_limited'}`뿐이고 키는 싣지 않는다. 키(userId)는 창 길이(1시간)+10초 안에 메모리에서 쓸린다. 지운 계정의 userId도 최대 약 1시간 메모리에 남지만, 무작위 uuid라 개인정보 흔적으로 보기 어렵다(기존 규칙과 같음).

### 2-4. 앱 — 통과(시험 공백 있음)
- 진입: `NoteSheet`의 `cloud` 묶음은 `cloudFlag && cloudDeps`일 때만 만들어지고, `view`는 거기에 더해 `readRecord(kv)?.state === 'on'`일 때만 생긴다. `MyDataSheet`도 `cloudFlag && cloudDeps`일 때만 그린다. **플래그가 꺼져 있으면 진입점이 0개다.**
- 시트는 기록을 바꾸지 않는다: `loadMyData`는 `readToken`과 `api.myData()`만 부른다. 다만 시험은 '세션 없음' 갈래에서 `mong.cloud.v1`만 비교한다. `401 no_account` 갈래에서 세션을 지우는 변이(A5)가 살아남았다 → 낮음 L3.
- 지우기 연결: 보기 시트를 닫은 뒤 맡겨 두기 시트를 입구 `'delete'`로 열고, `reduce(init, askDelete)`를 탄다. 그래서 켜짐이면 인장 코드 끝 네 자 확인(`deleteConfirm`)이 나오고, 다른 자리면 그 자리 그대로다. **기존 C12 확인을 우회하지 않는다.** 확인을 건너뛰는 변이 A1은 잡혔다.
- 문구: 재촉·공포 낱말은 없다. noAccount의 '글귀와 인장 코드로 웹 삭제'는 12절 '공유 링크 코드와 되찾기 글귀'와 같은 뜻이다(인장 코드 = 링크 키). 다만 시험 정규식이 활용형을 놓친다(A3 '서둘러' 생존) → 낮음 L4. '정리 예정일'은 운영자 삭제 요청 대기(`delete_requested_at`+72시간)를 뜻하는데, 이용자가 그 뜻을 알기 어렵다 → 낮음 L8.
- 접근성: 줄마다 `accessible`과 '이름, 값' 라벨이 붙고, 버튼은 role·라벨·높이 48이다. 줄은 `flexWrap`으로 감기고 `numberOfLines`는 없다. Android에서는 `announceForAccessibility`와 `accessibilityLiveRegion="polite"`가 같은 문장을 두 번 읽을 수 있다 → 낮음 L7.

### 2-5. 처리방침 12절·K39 — 병합 가(조건: 켜기 전 문장 수정)
열람 항목을 구현 줄(`myDataRows`)과 대조했다.

| 12절이 말하는 항목 | 화면 줄 | 일치 |
|---|---|---|
| 몽망이 수와 인장 코드 | creatures | O |
| 게임 기록과 이전 판의 크기·날짜 | save(날·획 수·크기) / versions(벌 수·합계) / version-i(사유·날짜·크기) | O(게임 기록의 '날짜'는 '마지막으로 맡긴 때' 줄) |
| 마지막으로 맡긴 때 | last | O |
| 되찾기 글귀·공유 링크 상태 | phrase / link(공개·꺼짐·가림 + 이름 실림 여부) | O |
| 계정을 만든 날·마지막으로 쓴 달·나이 확인 날 | account / age | O |

- **중간 M1 — 12절 이메일 행과 본문 글머리가 서로 반대다.** 표 행은 '정정·그 밖의 요청(**앱에서 볼 수 없는 열람 포함**) → 17절 이메일'로 바뀌었다. 그런데 바로 아래 글머리는 '이메일만으로 서버에 맡긴 정보를 보내 드리거나 바꾸지 않고 … 앱으로 할 수 없는 요청이면 그 사유와 이의를 내는 방법을 답장'이라고 한다. 실제로 앱에서 볼 수 없는 것은 세이브 본문(3-5: 생활 리듬·말결 분류값·이름 등), 공개 사본(메타·이미지·영상), 링크 일별 합계(`link_daily`, 코드 단위 30일)이다. 표는 '이메일로 열람할 수 있다'처럼 읽히지만, 실제 운영은 '거절하고 사유를 안내'다. 둘 중 하나로 맞춰야 한다. 예: 표 행을 '앱에서 볼 수 없는 항목의 열람 요청 — 17절 이메일(본인 확인 방법이 없으면 사유와 이의 방법을 답장)'으로 바꾼다. 또는 기록 내용을 보여 주는 길(내보내기)을 로드맵에 올린다. 법률 리뷰 질문 목록에 올릴 것을 권한다.
- **중간 M2 — 열람 항목 문장 ≠ 구현.** 방침 머리 원칙은 '넓게도 좁게도 쓰지 않음'이다. 그러니 ko·en에 '연결된 로그인 수, (있으면) 운영자 정리 예정일, 게임 기록의 날 수·획 수'를 더하고, '기록 안의 내용은 옮겨 적지 않습니다'를 '기록 안의 글씨·이름·좌표 같은 내용은 …'처럼 날·획 수(서버가 이미 따로 둔 열)와 구별되게 고칠 것을 권한다. 지금 시험은 행 **이름**만 대조하고 항목 목록은 대조하지 않는다(문구가 한쪽만 바뀌어도 통과한다).
- K39는 구현과 맞는다(본문·이름·글귀 해시·sub 없음, 인증·본인 것만·30/시간·no-store, 파일 경로가 모두 존재). 병합해도 된다. 상태 칸의 '구현'은 리뷰 뒤 '일치(커밋)'로 고칠 것.
