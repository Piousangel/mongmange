## Medium

### M-1. 앱 쪽 '플래그 꺼짐 = 빌드 1' 시험이 가드를 지키지 않는다
- `apps/mobile/test/m2.test.ts:50-58`: ① 시험은 `setName`을 **먼저** 보낸 뒤 `namePromptNow`를 부른다. 그러면 core `namePromptDue`의 `if (s.name) return false`에서 이미 false가 나온다. 그래서 `apps/mobile/src/game/naming.ts:29`의 플래그 가드를 지워도 통과한다(A1).
- 실제 위험: 플래그가 꺼진 새 세이브(이름 없음)에서 첫 재우기에 이름 창이 열린다. 그 뒤 `setName`이 세이브에 기록된다. 그러면 core 시험 ⑥이 전제로 삼는 '꺼짐이면 앱이 setName을 보내지 않음'이 앱 쪽에서는 어떤 시험으로도 고정되지 않는다(D-13).
- `sharedName`(`naming.ts:18`)도 같은 문제다. '꺼짐 + nameVisible 켬' 조합을 시험하지 않는다(A2). 지금은 nameVisible이 늘 false라 실제 피해는 없다. 다만 C11이 공개 스위치를 열면 바로 드러난다.
- 권고: ① 이름 없는 새 상태 + 꺼짐에서 `namePromptNow(s,'sleep')`가 false인지 본다. ② `setMeta({nameVisible:true})` + 꺼짐에서 `sharedName`이 null인지 본다. 이 둘을 더하면 A1·A2가 떨어진다. 가능하면 '꺼짐에서 GameApp이 setName을 dispatch하지 않음'도 화면 시험으로 고정한다.

### M-2. 이름의 문을 정규식 한 줄로 지키고 있어 쉽게 우회된다. 문도 싱크가 아니라 중간에 있다
- `apps/mobile/test/m2.test.ts:90`의 `/\bname\??\.text\b/`는 non-null 단언(`name!.text`), 별칭(`const n = s.name; n?.text`), 구조 분해 뒤 괄호 접근(`nm['text']`), 상태 통째 직렬화(`JSON.stringify(state)`)를 놓친다(탐침 4/4 통과). 검사 범위도 `share/`·`render/`·`cardText.tsx`뿐이다.
- 구조 문제: `MorningScreen.tsx:243`·`NoteSheet.tsx:205`는 **앱 안 이름(displayName)을 넣은 labels**를 그대로 `ShareBar` input에 넘긴다. 이 이름은 `cardText.tsx:94`의 `shareInput(input, owner)` 한 곳에서만 덮어쓴다. 앞으로 다른 화면이 `shareDreamCard`(싱크)를 직접 부르면 앱 안 이름이 PNG에 그대로 실린다. 정적 시험은 이 경우를 잡지 못한다(cardText 밖 screens는 검사 범위가 아니고, 이름 문자열은 `labels.name`으로 흘러 `name.text`가 나타나지 않는다).
- 권고(구조로 막기, 문서 한 줄 아님): ① `shareDreamCard`가 owner(또는 공유 이름)를 필수 인자로 받아 **싱크 안에서** 이름 줄을 다시 쓰게 하거나, ② 공유용 입력 타입에서 `labels.name`을 빼고 싱크가 `sharedName`만으로 채우게 한다. 정적 시험은 '이름 직접 읽기 0'보다 '공유 싱크가 sharedName/sharedNameOf 외의 이름 출처를 받지 않음'을 런타임 시험으로 바꾸는 편이 낫다. 예: displayName이 있는 상태로 모든 공유 진입점을 불러 결과에 이름이 없는지 본다.

1. **결정성**: ⑥이 세 변이를 모두 잡는다. 옛 세이브(name null)는 `parseState` 왕복 시험이 열리는 것을 확인한다. 메타는 `loadMeta`가 `nameAsk` 형식 검사·`nameVisible === true`로 미래·손상 값을 접는다. State 타입 변경은 Effect 한 종(`named`)뿐이라 세이브 형식 변화가 없다. 단, 앱 쪽 가드는 M-1.
2. **이름의 문**: `name.text` 읽는 곳 전수(앱): `game/naming.ts:13`(displayName)·`:19`(sharedName→core), `GameApp.tsx:548`(이름 바꾸기 창 초기값), core `sharedNameOf`·`melodyOfState`·`ireShareSourceOf`(sharedNameOf 경유). 공유물 경로는 카드 PNG(`shareInput`), 이레 영상(`nameVisible: sharedName(...) !== null`, `ireVideo.ts:141` 꺼짐 재확인), 두루마리 이미지(이름 미사용)이고 모두 닫혀 있다. 핑에는 시각만 실린다. `console.warn`에 이름 없음. 앱은 공개 스냅숏을 아직 올리지 않는다(`serializePublicSnapshot` 호출 0). 시험 우회는 M-2.
3. **입력**: 앱(`nameInput.ts`)과 서버(`page.service.ts:81`)가 같은 core `normalizeName`을 쓴다. 서버 금칙어 접기(소문자·공백·가운뎃점)와 `melodyKey` 접기가 같다. 조합 중 자모는 안내 없이 대기하고, 확정 시에는 거부된다(시험). 서브셋 밖 한글은 막지 않고 안내만 한다. 허용 라틴·숫자·'·'·공백은 서브셋에 전부 있다(직접 확인). 200%: 입력은 네이티브 자동 확대(웹만 fs 적용, 상한 2배), 세로 이름은 fs ≥ 1.5에서 가로로 바뀐다. 캡처 fs200 4장 있음, errors.json 빈 배열. 이름 지우기 길 없음(빈 입력은 확정 불가, core는 null로 못 바꿈).
4. **소리**: 비트 동일 48/48 확인. 엔진 변경은 `play(event, cueIn?, fixedRate?)`의 선택 인자뿐이다. 기존 호출은 `fixedRate` undefined로 같은 난수 경로를 탄다(난수 소비 순서 불변). 소리를 꺼도 햅틱은 남고(시험), `hapticsEnabled`를 지킨다. iOS 무음 스위치는 기존 ambient 세션 그대로다. 크기는 L-1.
