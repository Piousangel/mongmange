## 지적 (H 높음 · M 중간 · L 낮음)

### H-1 프레임 펌프 규격(PNG base64/프레임)이 12-05 관문을 구조적으로 못 넘길 위험 — `apps/mobile/src/share/ireVideo.ts:22-25`, `render/ireVideo/renderFrame.tsx:15-35`
- `IreEncoder.encode(spec, frame: (i) => Promise<DreamCardImage>)` — 프레임마다 drawAsImage(React 트리 마운트) → 두 번째 surface에 복사 → **PNG 인코딩 → base64 문자열** → 네이티브가 다시 디코딩해야 한다.
- 캡처 로그(`docs/app/c7/capture-log.json`) 기준 데스크톱 Chrome GPU에서도 **프레임당 170~240ms** → 240프레임 ≈ 45초. D-20 관문은 "중급 Android에서 240프레임 + 소리를 15초 안"(프레임당 약 60ms 예산). 웹 숫자라 네이티브와 다르지만, PNG 압축+base64만으로도 1080×1920에서 예산 대부분을 쓴다.
- 이 인터페이스가 C10 네이티브 모듈의 계약이 되므로, 모듈을 만들기 **전에** 바꾸는 게 싸다: 원시 RGBA(`readPixels` → ArrayBuffer/JSI) 또는 네이티브 공유 텍스처, 프레임 순차 호출 명시, PNG 경로는 디버그 전용. PM 답 ④(해상도 하향은 측정 뒤)와 별개로, 측정 전에 정해야 할 것은 **전달 형식**이다.
- 메모리: 프레임당 최고 약 25MB(art 8.3 + surface 8.3 + snapshot 8.3, 그리고 base64 문자열)이고 매 프레임 dispose되므로 누적은 없다. 다만 계약에 "frame(i)는 이전 Promise가 끝난 뒤에만 호출"이 없어 네이티브가 미리 당겨 부르면 그만큼 겹쳐 쌓인다(저메모리 Android OOM). 계약 주석·시험에 순차 호출을 박을 것.

### M-1 OS로 넘기는 MP4의 파일명·메타데이터가 계약에 없다 — `share/ireVideo.ts:24`, `share/native.ts:37-48`
- 이미지판은 `shareFileName()`으로 `mongmangi-ire-{밤}-9x16.png`을 앱이 정한다(이름·날짜·코드 없음). 영상은 **인코더가 돌려준 uri를 그대로** 공유한다 → 파일명·MP4 `©nam`/title·creation_time·위치 메타를 네이티브 구현자가 마음대로 정할 수 있다. 받는 앱(카톡·드라이브)이 파일명·제목을 보여 주므로 이름이 새는 표면이다.
- 권고: `IreVideoSpec`에 `fileName`(앱이 `shareFileName` 계열로 결정, 예 `mongmangi-ire-9x16.mp4`)을 넣고 "제목·위치 메타 쓰지 않음, creation_time은 0 또는 인코딩 시각만"을 계약 주석으로 고정, 시험으로 spec.fileName에 이름 문자열이 없음을 단언. 공유 캐시 정리도 지금은 "다음 공유 때 인코더가 정리"라고만 적혀 있어 `SHARE_DIR`(sharePng가 비우는 폴더)과 같은 곳에 쓰도록 맞추면 실패·취소 때 남은 부분 파일까지 한 규칙으로 정리된다.
- 현재 프레임·접근성 문구: nameVisible 꺼짐이면 재료에 `name` 키 자체가 없고(`ireScroll.ts:111`), 웹 루프는 `text:false`라 `ireTextItems`가 빈 배열(`ireScroll.ts:316`) — 런타임에 any/JSON으로 `name`을 끼워도 루프 프레임엔 그려지지 않는다(시험 `ire-scroll.test.ts:234-246`로 확인). 대화 제목은 `share.dialog`('꿈 카드 보내기')로 이름 없음. **프레임 경로는 안전**하다.

### M-2 중간 취소·언마운트가 없다 → 떠난 화면에서 공유 시트가 뜰 수 있음 — `share/ireVideo.ts:61-76`, `screens/cardText.tsx:59-75`

- 권고: `encode(spec, frame, signal: AbortSignal)`을 계약에 두고 ShareBar 언마운트 시 abort, abort면 이미지판으로도 떨어지지 않고 조용히 종료(결과 'cancelled' 같은 새 값 — 지금 `ShareResult`에는 취소가 없다).

### M-3 '두 번 공유' 경로 — `share/ireVideo.ts:69-70`
- `shareFile`이 `shareAsync`에서 throw하면 'failed' → 이미지판 시트가 이어서 뜬다. 시트가 이미 열렸다가 닫히며 throw하는 경우(Android 일부 받는 앱·권한 오류)엔 사용자가 시트를 두 번 본다. 폴백은 **시트를 열기 전 실패**(isAvailable false·인코딩 실패)에만 적용하고, 시트를 연 뒤의 실패는 'failed'로 끝내는 게 맞다.

## 확인된 좋은 점
- 결정성: 같은 이벤트 열·세이브 왕복 → 240프레임 완전 일치, 시계를 거꾸로 돌린 세이브도 재정렬 안 함, 픽셀 단위 같은 프레임(skia 시험).

- 프레임 수: 240/192는 상수, 길이는 `frames/fps`로 정확히 8000ms, 범위 밖은 clamp, 펌프는 비정수·범위 밖 거절. 반올림 어긋남 없음(M2·M3 잡힘).
- 루프 이음: 첫 프레임 먹 0(픽셀 0), 끝 프레임 fade 0.03, 포스터 181번은 fade 1.

- ShareBar 변경 1줄: 플래그 꺼짐(기본)이면 `shareIreScroll(state, look)` 그대로라 기존 동작 불변. 잠금·언마운트 처리도 그대로.
- 웹 `shareFile`은 'unavailable' → 이미지판, 렌더 웹 판은 2D 캔버스 글로 한글 처리.
