## 2. 질문별 판정

### ① 시각
**검댕은 해결됐다(통과).** `compare-day7` 하단 두 줄에서 C의 몸은 매끈한 방울 + 곧은 빗 세 획이다. 스파이크 02(위 오른쪽)의 톱니·털 가장자리와 확실히 다르다. 서툰 손 7획(맨 아래 줄)도 몸이 커지지 않는다. 몸 아래 `테`와 눈 둘도 살아 있다.

남은 시각 위험(캡처 근거, 심각도 순):

1. **높음 — 몸 아래 '받침'이 발·부스러기로 읽힌다.** `day7-C.png` 몸 아래, `compare-extra` 위 왼쪽에 작은 회색 덩어리 여러 개가 몸 아래에 뭉쳐 있다. 아트 1-4에 이번에 추가한 행("몸 아래 떠 있는 짧은 진한 획 → 바닥 담묵으로 해결")이 캡처에서는 해결되어 보이지 않는다. 진하지 않을 뿐 구슬처럼 이어진 덩어리라 "발"이나 "흘린 부스러기"로 읽힌다. 밤에는 `groundOpacity`가 0이라 받침 획이 사라진다(밤에 획 하나가 몸에서 빠짐, 낮밤 불일치). 조치: 받침은 한 덩어리 번짐 띠 1개로 합치거나(획별 구슬 금지), 번짐 고리(바닥 담묵 타원)에 흡수하고 밤에도 남긴다.
2. **높음 — 귀·후드.** 서툰 손(`day7-clumsy-C`, `compare-extra` 오른쪽 위)에서 왼쪽 위 큰 회색 획이 머리 위로 솟아 **고양이 귀·뿔·후드**처럼 읽힌다. 밤(`night-C`)에서는 왼쪽 위 획이 "손 든 팔/귀"다. 밤은 몸과 획의 농도 차가 1.30:1이라 획이 몸의 일부 부속물로 보인다. 기준 포즈(`compare-day7` C 기준)는 후드까지는 아니지만 왼쪽 둥근 획이 헤드폰 한쪽처럼 보인다. REPORT가 "귀: 여지(L3 후드)"로 적은 건 정직하나, 서툰 손 기본(L2)에서도 이미 나온다. 판정 표에서 이 칸은 "여지"가 아니라 "걸림(서툰 손 L2·밤)"이 맞다. 조치 후보: 정수리에서 왼쪽 위 −25°~ 사이(귀 자리)에 오는 획의 돌출 상한을 더 낮추거나 금지 자리 ③ 추가, 서툰 손 세트에 "머리 왼쪽 위로 곧게 솟는 획"을 넣어 최악을 먼저 본다.
3. **중간 — 담묵 획이 때·얼룩으로 읽힐 위험.** 근거 둘. (a) 획이 한 번도 몸 앞을 지나지 않고 전부 몸 바깥에 놓여 "그은 선"이 아니라 "묻은 회색 덩어리"에 가깝다(REPORT도 인정, `02a`와 가장 큰 차이). (b) `compare-day7` C 왼쪽 획 안쪽에 물결 모양 결(나뭇결·지문)이 보인다. REPORT는 이를 B의 문제로만 적었는데(비백 나뭇결 = B 여지) C도 같은 무늬가 나온다(비백 0.55). 담묵 회색 + 물결 무늬는 "물얼룩·때"의 전형이다. 조치: 비백을 길이 방향 줄무늬만 남기고 폭 방향 물결을 줄이거나, 획 끝 30%에만 둔다. 획이 몸 앞을 지나는 1.x 후보를 "남은 위험"이 아니라 **다음 스파이크 필수 항목**으로 올릴 것.
4. **중간 — "예 / 예" 판정은 작성자 둘의 합의다.** REPORT 2절 머리에 "외부 응답 아님"을 적은 건 좋다. 다만 "몽망이로 보이나 / 내가 그었다 = 예 / 예"를 결론(0절)에서 사실처럼 쓰면 안 된다. 캡처로는 "몽망이로 보인다: 예(몸 때문에). 내가 그었다: 반쯤(회색 부속물이라 내 획 같은 느낌이 약함)"이 정직하다. OPERATING 0-1의 "독창·세련·우아"에서 우아함은 "중간 이상"으로 적었는데, 서툰 손 캡처는 "중간"에 가깝다.
5. **낮음 — 밤 대비.** `stroke-ink` 밤 3.08:1(바탕) > 아트 4절 "ink-faded 장식만" 기준과 달리 본문 UI 3:1은 겨우 통과. 획이 몸과 1.30:1이라 밤에 획이 몸에 붙은 한 덩어리처럼 보인다(위 2번과 같은 뿌리). 비백 끔(`dry × (1-night)`)이라 밤 획은 평면 회색이다.

### ② 코드
**테스트가 의미 있나: 절반.**
- 의미 있음: 틈 테스트(앵커에서 gapRamp×1.6 이후 표면 거리 ≥ gap−0.012, B·C·두 세트), 금지 자리 점 단위 비율(≤15%, L1~L3, 두 세트: 정의상 참이던 이전 테스트를 결과 기반으로 바꿨다), L3 감기(표면 거리 ½ 이하), L2 상한 수치.
- **동어반복 1**: "E 빗 뿌리가 모두 금지 자리 ①(빗에서 파생) 안". `deriveForbidden`이 `combRootThetas`의 최댓값 + 6°로 구간을 만들고 테스트가 같은 `combRootThetas`로 안에 있는지 본다. 참일 수밖에 없다. 실제로 지키는 건 "45°~85°" 밴드뿐이다. 밴드는 유지하고 동어반복 부분은 지워라(낮음).
- **동어반복 2**: "끝 폭 ≥ 0.03W". `tailMin`이 0.32~0.36 × baseWidth 0.12~0.125 = 0.04 이상으로 정해져 있어 어떤 값이든 통과한다. 의미 있는 건 "가닥의 최소 폭"이 아니라 **리본 전체 윤곽의 곡률 부호 변화 횟수·톱니 수**(이전 리뷰 제안)다. 이번에도 안 들어갔다(중간).
- **지표 의미가 바뀌었다(중간)**: "핵 면적 ≥ 실루엣 75%". 이 지표는 스파이크 02에서 "획이 몸 윤곽을 거칠게 만들었나"를 보려던 것인데, 이제 획은 몸 마스크 밖 회색 덩어리라 지표가 "획이 얼마나 많이 바깥에 있나"를 잰다. 서툰 손 C는 **75.0%로 문턱과 똑같다**(여유 0). 리본 기하의 합이지 렌더된 실루엣(닫힘·블러 뒤)이 아니다. 문턱을 넘는지가 아니라 마진을 보고, 렌더 캡처 기반 지표(몸 짙은 먹 마스크 대비 담묵 면적)로 바꿀 것.
- 빠진 것(중간): (a) `attachVersion 1` 기록을 옛 L3(반경 압축)로 그린다는 하위 호환 테스트가 없다(코드에는 분기가 있으나 `sim-save` 외엔 version 1 세이브로 `strokeLocal`을 검사하지 않는다). 아직 유저 세이브가 없으니 낮음이 될 수 있으나 D-13 "메시 개선해도 세이브가 안 깨진다"가 정본이면 필요하다. (b) `FORBIDDEN_ZONES`가 `COMB_REST`·`COMB` 수치에 의존하므로 빗 수치를 바꾸면 이미 저장된 `attach.theta`가 금지 구간에 들어가는 세이브가 생긴다. 저장된 attach는 안 바뀌니 보이는 결과는 그대로지만, 이후 `attachStroke` 재계산(마이그레이션)이 다른 값을 낸다. 의도라면 D-13에 한 줄 필요.

**worklet 순서 가드: 유지됨.** `comb.ts`의 새 최상위 `FORBIDDEN_ZONES = deriveForbidden()`은 `combStrands`·`combRootThetas`·`deriveForbidden` 아래에, 그것을 쓰는 `isForbiddenNow`는 위에 있다. 모듈 로드 시 JS 스레드에서 한 번 계산하고 worklet은 닫힘으로 잡으니 순환 import(comb → core, attach → comb)만 아니면 안전하다. `core.ts`는 comb를 import하지 않아 순환 없음을 확인했다. 가드 테스트는 정적 정규식이라 "최상위 `const`가 모듈 로드 시 worklet을 호출하는" 새 패턴(이번 `deriveForbidden()`)은 잡지 못한다(낮음, 순서만 지키면 됨).

**성능(덧칠 1패스): 비용은 "1패스"보다 크다(중간).**
- 레이어 안에 `Vertices` + SkSL 셰이더 덧칠 1패스가 늘었다. 이 자체는 작다(획 영역만 픽셀 셰이더, `vnoise` 3~4회).
- 하지만 프레임마다 `combStrands`가 3번 돈다(`combRibbons`, `inkVerts`, `freshVerts` 쪽 경로), `ribbonsToVerts`가 마스크·덧칠·바닥(`groundVerts`, 받침이 없어도 매 프레임 빈 배열 + 더미 정점) 3번 새 객체 배열을 만든다. 이전 리뷰 2-5의 GC 지적이 그대로고 늘었다.
- 획별 캐시에 리본이 2개(`rb`, `ov`) 든다(메모리 2배, 갱신 시 `buildRibbon` 2번).
- 부착 애니메이션 동안 `wrapPoints`가 `perimeterTable(s, 180)`(삼각함수 181번 × 2)을 그 획이 바뀔 때마다 새로 만든다. 핵 크기 s가 같으면 캐시할 수 있다(`s`별 1개).
- 닫힘 반경 1.5 → 0.6pt는 필터 비용을 줄여 준다(상쇄). S25·중급 Android 측정 항목에 "덧칠 패스 포함"을 명시.
- 이전 지적 "손획 `live` 배열 복사 O(n²)"는 이번에도 그대로다(범위 밖이면 REPORT 남은 위험에 한 줄 필요, 지금 3절에는 없음).

### ③ 정본 개정과 다른 문서의 충돌
- **높음 — 시스템 설계 v1.1 4.3 바램 표 충돌(REPORT 3-4가 인정하지만 수정이 아직 없음).**
