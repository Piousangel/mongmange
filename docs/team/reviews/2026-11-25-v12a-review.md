## 지적

### H1. 정반사 금지 검사가 '그럴듯한 오답'을 통과시킨다 — `apps/mobile/test/skia/light-metric.ts:85-109`, `body-light.test.tsx:34,81-86`
- 근거: V1b·V1c. 정반사를 실제로 막는 것은 범위 상한(0.08) 하나뿐이고, 낮 여유는 0.0125(실측 0.0675), 밤 여유는 0.010이다. 계수 0.25 정도의 정반사, 또는 밤 전용 정반사는 모든 시험을 통과한다. PM 판정대로 **낮을 high 1로 올리면** 낮 여유가 이 표의 값 그대로라 더 줄지는 않지만, 나중에 `lift.day`를 올리는 순간 여유가 사라진다.
- 고칠 방향(택1 이상): ① 셰이더 소스 정적 시험 — `bodyLightFx` 소스에 `pow`·`exp`·`reflect`·`dot(…H…)` 금지, `d`를 쓰는 항은 `up`·`dn` 두 줄뿐(가장 싸고 결정적, OPERATING 7 '교정은 검사로') ② 렌더 지표를 '램버트 모형 적합 잔차'로 — ΔL을 `a + b·dot(n̂, L)`(시험이 같은 돔 법선을 계산)에 맞춘 잔차 최대 ≤ ε. 정반사는 모양이 달라 잔차로 튄다 ③ 음성 대조를 합성 방울 대신 **실제 셰이더 변이**(V1c 꼴)로 바꿔 지표가 잡는지 고정.

### M1. PM 판정 '낮만 high 1'이 코드에 없다 — `packages/core/src/visual/bodyLight.ts:13-14`, `Mongmangi.tsx:272-273`
- 현재 기본 세기는 낮·밤 공통 `mid`. DECISIONS 마지막 줄(PM 11-25)과 코드가 어긋난다. 구현할 때 `night > 0.5`로 세기를 바꾸면 전환 중 한 번에 튄다 — **worklet 안에서 `lv = mix(lvDay, lvNight, f.night)`로 연속 보간**할 것. 시험은 세기 1(상한)에서 낮·밤 모두 보므로 범위 시험은 그대로 덮는다. 기본값 단언(낮 1·밤 0.75) 시험 한 줄 추가 필요.

### M2. 밤↔낮 전환 중 빛 방향 그림자 색이 한 프레임에 바뀐다 — `Mongmangi.tsx:643`
- `castColor = night > 0.5 ? #05070D : #5A4A36`. 불투명도는 보간되어 night 0.5에서 0.405인데, 그 순간 갈색 → 거의 검정으로 점프한다. 몸 칠도 `night/20` 단계와 테 색 0.5 스냅이 있지만, 그림자는 몸 밖 종이 위라 더 눈에 띈다. `lightCol`처럼 RGB 보간(또는 `interpolateColor`)으로. 시험 없음 → night 0.45·0.55 렌더 차이가 0.4·0.45 차이와 비슷한지 보는 연속성 시험을 추천.

### M3. 몸 먹(ink) < 1일 때 눈 위 그림자가 몸을 뚫고 보인다 — `Mongmangi.tsx:745-751`(`dstOver`), `makeBodyPaint`의 `paint.setAlphaf(ink)`
- `dstOver`는 '방금 뺀 구멍'만이 아니라 **바깥 레이어에서 알파 < 1인 모든 곳**에 깔린다. 먹이 차오르는 동안(ink < 1) 몸 전체가 반투명이라 위로 민 눈 사본(눈썹 자리)이 담묵 얼룩으로 비친다. `eyeShadowOpacity`에 ink를 곱했지만 결과는 `ink·0.5·(1−ink)`라 ink 0.5 근처에서 최대가 된다. 몸 가장자리 반투명 띠·블러 꼬리와 겹치는 큰 눈(LOD eyeScale)에서도 같은 일이 생길 수 있다. 시험의 눈 두께 단언은 ink = 1, 점 세 개만 본다. 고칠 방향: 불투명도를 `ink²` 이상으로 낮추거나 ink < 1에서는 끄기, 또는 눈 구멍 경로로 `clip`(웹 캡처 문제는 README 1절 ④ — 네이티브만 clip 분기). ink 0.5 렌더에서 눈 위 영역 ΔL 0 단언 추가.

### L1. `shadowT`가 렌더마다 새 worklet — `Mongmangi.tsx:617-625`
- Reanimated 4.7 네이티브 `useDerivedValue`는 의존성으로 `updater.__closure`를 쓴다(`useDerivedValueCommon.ts:30`). `castT`·`contactT`의 클로저에 렌더마다 새로 만드는 `shadowT`가 들어 있어 Mongmangi가 다시 렌더될 때마다 매퍼 두 개가 멈췄다 다시 시작한다(리뷰 M3 '렌더마다 새 배열 → 재직렬화'와 같은 범주). 모듈 최상위 worklet `shadowT(f, coreH, dx, dy, skew)`로 옮길 것. worklet 정적 시험(core)은 통과 — 이 범주는 잡지 않는다.
- 같은 맥락에서 `lightU`의 `[0,1,2].map(...)`은 매 프레임 배열·클로저 할당(무시할 수준, 세 원소 직접 쓰기 권장). `bodyLightFx`는 모듈 최상위 `make(...)` 한 번이라 RuntimeEffect 재생성 문제는 **없음**(확인).

### L2. 셰이더 사각이 필요 이상으로 크다(채움 비용) — `Mongmangi.tsx:612-615`
- `lightRect` = ±1.7·s W(3.4W 정사각). 120pt·3x에서 약 1200×1200 = 140만 px를 몸 하나마다 매 프레임 셰이딩한다. `srcATop`이어도 Skia는 dst 알파 0 픽셀까지 셰이더를 돌린다. 핵 경계 + 획 최대 길이로 줄이면 면적이 1/3~1/4로 준다. hop·기울기 여유는 경계 상자에 더하면 된다.

### L3. `distinct.test.tsx`에 넣은 빛 단언은 항진명제다 — `distinct.test.tsx:63-69`
- 크기가 22·36pt뿐이라 빛은 늘 꺼져 있고, 같은 픽셀임은 `body-light` ②가 이미 해시로 고정한다. RENDER_HEAVY 시간만 약 1.5배(결과 8 → 12) 늘린다. 지우거나 64pt 한 칸으로 바꿔 '빛이 켜진 크기에서 구별 지표가 나빠지지 않음'을 볼 것.

### L4. '빛은 화면에 고정'이 기울기 ≠ 0에서 시험되지 않는다 — `body-light.test.tsx`(④)
- 모든 표본이 tilt 0이다. 빛 노드를 `anim` 그룹 안으로 옮기는 변이(몸과 함께 도는 빛)는 통과할 것이다. ④에 tilt ±0.06 표본 하나를 더하면 막힌다.

### 정보(지적 아님)
- **꺼짐 = 기존 golden 동일**: 기존 mongmangi-render 시험 통과, ② 22·36·48pt 해시 동일(기본 18쌍, 전체 72쌍), 49pt부터 달라짐 — 48pt 경계 정확. `bodyLightT(NaN) = 0`도 고정.
- **48pt 기준의 뜻**: `bodyLightT(f.wpx)`는 핵 배율 s를 곱하기 전 폭이다. D-24 `bodyLod(bodyPt)`와 같은 입력이라 두 램프가 겹치지 않는다는 주장은 맞다. review.md 3-2의 '48pt 이하 선형으로 줄이고 24pt에서 0'과는 다르지만(이쪽은 48 이하 끔·48→60 켜짐) README·DECISIONS에 이유가 적혀 있다.
- **합성 순서**: 확산광은 획 칠(`strokeInkFx` srcATop) **뒤**에 같은 바깥 레이어에 얹혀 **획 위로도 빛이 올라간다**. 획은 몸 coverage의 일부라 물리적으로 맞고, 획 끝은 가장자리 법선으로 고정된다. 번짐 고리·접촉·방향 그림자는 바깥 레이어 밖(앞)이라 빛이 고리를 칠하지 않는다. 그림자 → 힌트 → 고리 순서라 고리가 그림자 위에 그려진다.
- **모션 줄이기**: 빛·그림자는 정적, hop만 따라 돔 중심이 움직인다. 모션 줄이기와 독립 — 문제 없음.
- **시험 시간(5번 안)**: 이미 '기본 = 줄인 표본, RENDER_HEAVY = 전체'로 되어 있다(`body-light.test.tsx:26`). 이번 측정 34초(80초는 load 30 이상의 전체 행렬과 섞인 숫자로 보임). 제안된 '체형 1 × 낮밤 2'는 ①에 이미 해당(낮 b0·밤 b2). 더 줄일 곳은 ②의 기본 18쌍(6.8초) → 경계 48pt·체형 1·낮밤 2·LOD 켬 1 = 4쌍과 22pt 1쌍이면 충분. 안 자체는 **타당**.

## 성능 근거(4번)

- `perf.json`은 headless Chromium·ANGLE **소프트웨어 래스터**의 rAF 간격(프레임 150ms 안팎 = 6~7fps)이다. CPU 래스터가 지배하고 load 30 안팎이라, 12마리 +6%·36마리 차이 없음은 둘 다 잡음 범위다. README가 '눈에 띄는 증가 없음까지만'이라고 한계를 적은 것은 정직하나, **이 수치는 GPU 채움 비용에 대해 아무것도 말하지 않는다**(근거로 인용 금지 권장).
- 위험은 실제로 GPU 채움: 이미 '닫힘 + 블러 + 색 행렬' 필터 그래프가 걸린 saveLayer 안에 140만 px 런타임 셰이더(L2) + 블러 경로 2(그림자, 해석적이라 캐시 가능) + `dstOver` 블러 경로 1.
- V20 항목은 **필요하지만 지금 문구로는 부족**하다. 추가할 것: ① 기기 = Mali-G52/G57급(중급 하단) + 3x 기기 하나 ② 장면 = 홈 한 마리 + **48pt 넘는 몸이 여러 마리 동시에 보이는 화면**(화첩·두루마리 큰 칸이 있으면 그것) ③ 지표 = fps가 아니라 GPU 프레임 시간(빛 끔·켬 차이 ≤ 1.5ms 같은 수치 기준), 열 쓰로틀 5분 뒤 ④ 실패 시 대안(L2 축소 → 정지 중 Picture 캐시) 순서.

## 아트(6번) — 시안 직접 확인(`grid-day.png`·`grid-night.png`·`zoom120-*`)

- **낮**: low·mid는 120pt에서도 몸 확산이 거의 보이지 않는다. high에서 왼쪽 위가 아주 살짝 옅어지는 정도 — PM의 '낮만 high' 판단에 동의. 보이는 변화의 대부분은 바닥 그림자다. 광택·밝은 점 없음. **조약돌·3D 마스코트로 읽힐 위험 낮음.** 눈 구멍 두께는 120pt 확대에서도 거의 안 보인다(현행 유지 판단과 맞음 — 눈동자로 읽힐 위험 없음).
- **밤**: mid가 '얇은 먹 막'으로 읽히는 적정선. high 120pt는 몸 전체가 왼쪽 위 → 오른쪽 아래로 고르게 흐르는 매끈한 그라디언트 + 밝은 테 선이 겹쳐 **비닐 스티커·말랑 피규어 쪽 인상이 시작된다**(조약돌까지는 아님). 밤은 mid 상한 유지 권장(PM 판정과 같음).
- **그림자 vs 번짐 고리**: 낮은 고리(먹 색 담묵, 파랑·갈색·보라)가 그림자 위에 그려져 고리가 여전히 이름표로 앞선다. **밤은 방향 그림자(55%, 거의 검정)가 수면 위에서 고리보다 먼저 눈에 들어오는 칸이 있다**(1.15·1.25 체형 120pt, 고리는 몸 아래 좁은 빛 띠로만 보임). 금지선('그림자가 고리를 가리면 안 됨')을 넘지는 않지만 V20 실기기에서 밤 그림자 세기(55 → 40%대)를 고리 판독성과 함께 볼 항목으로 추가 권장.
- 웹 캡처는 질감 판정 근거가 아니다(D-04) — 위는 상대 비교만.
