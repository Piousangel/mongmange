## 0. 요약

구조는 좋다. 키 정본(ko) → en 누락은 타입에서 막히고, 변수 이름도 타입으로 검사하며, 시 문구를 언어별로 따로 쓴다는 원칙도 지켰다. 한글 하드코딩 검사, 알림 재예약 큐도 갖췄다. 영어 카피는 톤(절제·느낌표 없음)은 대체로 맞는다. 다만 원어민 귀에 걸리는 번역투가 열 군데 남짓 있다. 특히 `Morning, Day 2`(인사말로 읽힘), `moist`, `a round moon`, `Send`, `is drawn`이 그렇다. 임시 호칭 `Mongmang`은 R5 후보 셋 중 어느 것도 아니다. 스토어 문안(`Mongmangi`)과도 어긋난다.

커밋 전 필수(P1) 4건: ① 임시 호칭을 `Mongmangi`로 ② 낮 문구 5곳 수정(`Morning, Day n`·`moist`·`is drawn`·자정과 정오 표기·`Send`) ③ 무관한 `@expo/ngrok` 의존성은 분리 ④ 320×568 200%에서 '목록으로 보기'와 몽망이가 겹침. ④는 작성자가 남긴 아침 카드 겹침과 별개 건이다.

## 3. ICU 자체 구현·번들·언어 전환

### 3-1. ICU
- **중첩된 select 안의 `#`이 숫자로 바뀌지 않는다(P2).** `{n, plural, one {{g, select, a {# A} …}} …}` 를 n=1로 돌리면 결과가 `# A`다(ICU 표준은 `1 A`). 원인: `parseMessage(r, type === 'plural')`가 select 가지를 `inPlural=false`로 읽는다. 바깥 inPlural을 물려받게 하면 된다. 지금 문구에는 이 꼴이 없다.
- **이스케이프 없음(P3, 결정대로).** 영어 아포스트로피에는 편하다. 대신 리터럴 `{` `}`를 쓸 방법이 없다(`Use { not`는 parse 오류). 문구에 중괄호가 필요할 일은 적다. 다만 D-17에 "리터럴 중괄호 불가"를 한 줄 적어 둔다.
- 숫자가 아닌 값이 plural에 들어오면 `NaN`이 찍힌다. 타입은 `string | number`라 막지 못한다. plural 변수만 number로 좁히는 건 다음 단계(P3).
- 빠진 변수는 `{name}`으로 그대로 보인다. 타입이 1차로 막으므로 괜찮다.
- 파싱은 키별 캐시가 있어 비용이 없다. 표 전체를 테스트에서 parse하므로 런타임 파싱 실패 위험도 낮다.

### 3-2. 번들
- i18n 코드·두 표: 수십 KB 수준. intl-messageformat보다 가볍다는 결정은 타당하다.
- **Cormorant 서브셋이 Medium 149KB, Italic 101KB로 크다(P2).** 라틴 206자 서브셋치고 무겁다. 흔한 라틴 서브셋은 각 30~60KB다. 힌팅 정보, 쓰지 않는 OpenType 기능(swash·ss·old-style 숫자 등), 화면에 안 나오는 Latin-1 기호가 남은 것으로 보인다. `subset-latin.mjs`에서 hinting과 layout feature를 정리하면 절반 이하로 줄 것으로 본다. 테스트 상한 200KB가 현 상태를 통과시키므로 상한도 낮추기를 권한다.
- 캡처에서는 숫자가 old-style로 나온다("Day 2"의 2가 x높이). 아트 6절 표의 '숫자 = Pretendard Tabular' 규칙과 날 세기 제목의 관계를 아트 쪽에서 확인해야 한다(P3).

### 3-3. 언어 전환·알림 경합
- `setLanguagePref`가 `current`를 동기로 바꾸고 알림은 마이크로태스크로 미룬다. `scheduleMorning`은 직렬 큐 안에서 await 뒤에 `t()`를 읽는다. 빠르게 두 번 바꿔도 마지막 언어로 예약된다. **경합 문제 없음.**
- **Android 알림 채널 이름이 첫 언어로 굳는다(P2).** `setup()`은 프로세스당 한 번만 돈다(`ready`). 그래서 언어를 바꿔도 시스템 설정의 채널 이름은 '아침 꿈'/'Morning dream' 중 처음 것이 남는다. 언어 바뀜 구독에서 `setNotificationChannelAsync`를 다시 부르면 이름이 갱신된다.
- **'기기 따름'일 때 기기 언어 변경을 다시 읽지 않는다(P3).** `device ??= deviceTag()`가 프로세스 동안 고정된다. iOS는 언어를 바꾸면 앱을 재시작하므로 괜찮다. Android는 구성 변경 뒤에도 JS가 살아 있을 수 있다. 앱이 앞으로 올 때(AppState active) device를 다시 읽고 바뀌었으면 알리는 편이 안전하다. 같은 이유로, 밤사이 기기 언어가 바뀌면 이미 예약된 알림은 옛 언어로 온다(허용 가능).
- `MorningScreen`의 `labels` useMemo는 `text`(현재 언어로 만든 문장)에 의존하므로 언어가 바뀌면 다시 계산된다. 문제 없음.
- 언어 이름 '한국어' 행은 영어 스크린리더 음성으로 읽힌다. `accessibilityLanguage="ko"`(iOS)를 그 행에만 주기를 권한다(P3).
- `wakeClock`은 항상 12시간제 a.m./p.m.이다. 반면 노트의 `clockTime`은 en-GB 기기에서 24시간제를 따른다. 한 화면 안에서 표기가 엇갈릴 수 있다(P3).

### 3-4. iOS 감지
- `CFBundleDevelopmentRegion=en` + `CFBundleLocalizations=[en, ko]` + `CFBundleAllowMixedLocalizations=true`. 일본어 기기 → en, 한국어 기기 → ko로 풀리는 구성은 맞다. 확정 조건대로 다음 EAS 빌드 실기기에서 두 언어를 반드시 확인한다(Hermes `resolvedOptions().locale`가 앱 언어를 따르는지는 실기기에서만 확인된다).

## 4. 정적 검사(한글 리터럴 금지)

### 4-1. i18n-ignore 13줄 + 파일 1개 — 정당한가
- `IntroScreen.tsx` 218–225 (7줄): 소리·햅틱 개발 자막. `captions = PARAMS.cap`(?cap=1) 또는 GameApp의 `__DEV__ && meta.devCaptions`일 때만 보인다. **정당.**
- `StrokeScreen.tsx` 135·313–315·334·424 (6줄): 스파이크 계측·개발 자막·스파이크 버튼. `!game`·`!clean && !game`일 때만 그린다. 스파이크 화면은 네이티브에서 `__DEV__` 개발 메뉴로만 열린다. **정당.** 단 웹 빌드에서는 `?screen=stroke`로 누구나 열 수 있다. 웹을 공개 배포한다면 웹에서도 스파이크 경로를 `__DEV__`로 막는다(P3).
- `DevPanel.tsx` 파일 전체 `i18n-ignore-file`: `__DEV__`에서만 렌더. 정당. 접근성 라벨 '개발 메뉴'가 영어 캡처의 aria 목록에 나오는데, 이것도 개발 빌드 전용이다.
- 상한 `≤ 13`은 지금 개수와 딱 같아 새 예외가 생기면 바로 실패한다. 좋다.

### 4-2. 우회 구멍
1. **영어(라틴) 하드코딩은 못 잡는다(P2).** 검사는 한글만 본다. 그래서 `accessibilityLabel="Back to app"`(App.tsx, 개발 전용이라 지금은 OK), 'raw JSON' 같은 글이 그대로 통과한다. 한국어 사용자에게 영어 글이 새는 경로가 열려 있다. 보완: JSX 텍스트 노드와 `accessibilityLabel|accessibilityHint|placeholder|title=` 속성의 문자열 리터럴을 따로 잡는 규칙을 둔다(라틴 포함). 예외는 같은 i18n-ignore로.
2. `i18n-ignore-file:` 한 줄이면 어떤 파일이든 통째로 빠진다. 개수 상한이 파일 단위 예외에는 걸리지 않는다. 허용 파일 목록(현재 DevPanel만)을 테스트에 박아 둔다(P2).
3. 같은 줄 판정이다. 여러 줄 템플릿 문자열의 한 줄에만 표시가 있으면 나머지 줄은 걸린다(안전한 쪽). 반대로 한 줄에 사용자 문구와 개발 문구가 함께 있으면 둘 다 빠진다. 지금은 해당 없음.
4. `console.*`·`new Error(`가 있는 줄 전체가 면제다. `throw new Error('…'); setLine('한글')`처럼 한 줄에 붙여 쓰면 빠진다. 드물지만 구멍이다(P3).
5. 스캔 대상이 `src`, `App.tsx`의 `.ts/.tsx`뿐이다. `app.json`의 권한 문구(iOS `NSUserNotificationsUsageDescription` 등을 앞으로 넣을 때)와 `.js`는 보지 않는다. Info.plist 문구는 `InfoPlist.strings` 현지화가 따로 필요하다는 점도 기록해 둔다(P2, 다음 단계).
6. `packages/core`는 스캔하지 않는다. core가 화면 문장을 내지 않고 키만 낸다는 전제(sim-impl 2절)를 지키는 한 괜찮다. core에 한글 문자열이 없다는 검사를 하나 더 두면 전제가 깨질 때 바로 보인다(P3).
