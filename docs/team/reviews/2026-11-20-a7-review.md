## 판정 요약

결함 원인 규명(GPU 블러 마스크 문턱)과 수정 방향은 타당하고, 플래그 꺼짐·2x 이상·48pt 초과의 픽셀 불변은 실제로 de90b3d와 일치함을 확인했다. 머지 막는 결함(Critical)은 없다. 다만 **"48pt 초과 픽셀 불변"은 밀도 조건이 붙는 주장**이고, **구별 지표 테스트는 '구별 개선'을 증명하지 못한다**. 아래 Important 2건은 문서·테스트 표현을 바로잡는 수준이면 된다.

## 발견

### Important

**I-1. 블러 하한은 1x·1.5x 밀도에서 48pt 초과에도 작동한다 — "큰 화면 픽셀 불변"은 dpr ≥ 약 1.74에서만 성립**
- `Mongmangi.tsx:503` 눈 구멍 `maskSigmaW(0.006, wpx, dpr)`: 하한이 걸리는 조건은 `0.006·wpx·dpr < 0.5` → `wpx < 83.3/dpr`. 1x는 83pt 미만, 1.5x는 55.5pt 미만, 2x는 41.7pt 미만, 3x는 27.8pt 미만.
- 실측: `64pt@1x` 해시가 de90b3d와 다르다. golden 사례(`cases.ts:17`)는 49@2·64@2·96@3·120@1로, 1x에서는 83pt를 넘는 120만 골라 이 구간을 덮지 않는다. `mongmangi-render.test.tsx`의 제목 "48pt 초과, 밀도 1~3"은 과장이다.
- DECISIONS D-24(284줄)는 "2x 이상·48pt 초과"로 바르게 적었지만, 아트 바이블 1-5(128줄)·`features.ts` 주석·작성자 주장 ②는 밀도 조건 없이 "48pt 초과 = 정본 그대로·픽셀 불변"이라 적었다.
- 영향: 1x 데스크톱 웹·1.5x 안드로이드(hdpi)에서 48~83pt 몸의 눈 가장자리가 σ 0.38px → 0.5px로 아주 조금 더 흐려진다. 시각 차는 작고 의도한 수정 방향이지만, "불변"이라는 문장은 틀렸다.
- 권고: 아트 바이블 1-5·12절에 "LOD는 48pt 초과에서 꺼짐. **블러 하한은 크기가 아니라 장치 px 기준이라 저밀도에서는 48pt 초과에도 걸린다**"를 덧붙이고, golden에 `64@1`(하한 작동, 새 해시로)·`49@1.5`를 넣어 그 구간을 의도된 변화로 고정한다.

**I-2. 구별 지표 테스트(`distinct.test.tsx`)는 '구별 개선'을 증명하지 못한다(단언이 대비 증가로 거의 자동 성립)**
- `distinct.test.tsx:59` `accuracy === 1`은 현행·LOD 모두 1이라(metric.json 8조건 전부) 포화. 두 방식을 가르지 못한다.
- `distinct.test.tsx:63-64` "LOD 쌍 거리 > 현행 × 1.2"는 절대 거리 비교다. LOD는 획 채도 ×2.2·폭 ×1.36·눈·빗 ×1.3으로 **대비 자체를 키우므로** 서로 다른 개체 사이 거리뿐 아니라 '크기만 다른 같은 개체' 거리도 함께 커진다. 실측(metric.json): same 중앙값 0.0008 → 0.0022(약 2.8배), 정규화 여유 `marginMedian`은 8.42 → 5.16(mixed-36), 4.19 → 2.76(handOnly-36)으로 **악화**. JND 문턱을 뺀 거리라 대비가 커지면 문턱을 넘는 칸이 늘어 효과가 부풀려진다.
- 즉 이 테스트가 고정하는 것은 "LOD가 픽셀 대비를 키운다"이지 "사람이 개체를 더 잘 가른다"가 아니다. 작성자가 여유 비 악화를 보고만 하고 단정하지 않은 것은 정직하지만, 아트 바이블 15절 위험 13이 이 테스트를 '자동 지표'로 인용하므로 오해 소지가 있다.
- 권고: (a) 단언을 정규화 지표로 바꾸거나(예: `marginMedian`이 현행 대비 일정 이상 떨어지지 않음 = 회귀 가드), (b) 질의 잡음을 실제에 가깝게(1px 평행 이동·자세·축소 후 재샘플) 바꿔 accuracy가 포화되지 않게 하고, (c) 문서에서 "구별 개선의 판정은 12-05 블라인드, 이 테스트는 대비·회귀 가드"로 지위를 낮춘다.

### Minor

**M-1. 무거운 테스트가 기본 스위트에 있다.** mobile `vitest run`이 187초(이전 스위트는 수 초 수준). `distinct.test.tsx`는 테스트당 타임아웃 600초, 32회×4조건 렌더. 기본 `pnpm test`·Stop 훅·CI 피드백이 느려진다. 권고: `distinct`는 `A7_DISTINCT=1`일 때만 돌리거나 `test:slow` 스크립트로 분리, 기본 스위트에는 `mongmangi-render`(약 30초)만 둔다.

**M-2. CPU 밝기 검사는 결함을 잡지 못한다.** `mongmangi-render.test.tsx:67`(22pt·2x 눈 자리 밝기 > 150)은 하한을 제거해도 통과했다 — CPU 래스터는 원래 눈을 그리기 때문이다(작성자 프로브도 "CPU 정상"이라 적음). 결함을 실제로 잡는 것은 MakeBlur sigma 스파이 검사 하나뿐이다. 밝기 검사는 "LOD·하한이 눈을 망가뜨리지 않음" 가드로는 유효하니 남기되, 주석 ①의 "눈 소실 결함 회귀"를 "sigma 검사가 회귀 가드, 밝기 검사는 보조"로 고친다. core `lod.test.ts:96`의 `maskSigmaW(...)·wpx·dpr ≥ 0.5`는 `Math.max`의 정의를 다시 쓴 동어반복이다(해는 없음).

**M-3. 0.5px 근거는 한 환경의 프로브 하나.** `scripts/a7-gpu-blur-probe.mjs`(헤드리스 Chromium, ANGLE-Metal, CanvasKit WebGL)에서 0.32 사라짐 / 0.34 그려짐, 0.5는 약 1.5배 여유. 네이티브 RN Skia(iOS Ganesh-Metal, Android Ganesh-GL/Vulkan)는 같은 Ganesh 블러 경로라 같은 문턱일 가능성이 높지만 **실기기 미확인**(DECISIONS에도 그렇게 적힘). Graphite 백엔드를 켜면 다를 수 있다. 하한은 그리는 쪽으로만 작동해 네이티브에서 문턱이 더 낮아도 해는 없다. 권고: S25 실기기에서 `?view=thumb` 22pt·36pt 캡처 1장으로 확인하고 DECISIONS에 결과를 적는다.

**M-4. 꿈 카드 본화면도 플래그를 켜면 LOD가 약하게 걸린다.** `DreamCard.tsx:342`에서 화면 카드(폭 약 340pt)의 1W = 0.128 × 340 ≈ 43.5pt → t ≈ 0.19 → 첫날 카드의 감은 눈·빗이 ×1.06. 1-5 규칙("몸 폭 기준")과는 맞지만 "썸네일만 바뀐다"는 인상과 다르고, 같은 카드의 공유 PNG(`renderImage*.tsx`는 opts를 넘기지 않음 → LOD 꺼짐)와 화면이 미세하게 다르다. 의도라면 1-5 적용 범위에 한 줄 적는다.

**M-5. 테스트가 선언하지 않은 전이 의존성을 쓴다.** `test/skia/headless.ts`가 `canvaskit-wasm`을 `require`하지만 어떤 package.json에도 선언이 없다(@shopify/react-native-skia의 전이 의존성이 루트에 끌어올려져 있어 동작). pnpm 끌어올림 설정이나 Skia 버전이 바뀌면 깨진다. "새 의존성 없음"은 사실이지만, 의존이 숨어 있다. 권고: `require.resolve('canvaskit-wasm/...', { paths: [skia 패키지 경로] })`로 Skia 쪽에서 찾거나 devDependency로 고정 버전 선언.

**M-6. LOD 켬 + 몸 폭이 바뀌면 JS 재렌더가 0.5pt마다 일어난다.** `Mongmangi.tsx:265` 키 넷째 칸이 48pt 초과에서도 `wpx`를 담아, t = 0인데도 칠 페인트·`L`·`slotRgb`가 다시 만들어진다. 지금은 화면마다 `wpx`가 레이아웃 고정값이라 실제 해는 없음. 확대·성장 애니메이션이 `wpx`를 움직이게 되면 문제. 권고: `Math.min(wpx, 48)`로 양자화(48 초과는 한 키).

### 확인했고 문제 없음

- **worklet 규칙**: `lod.ts`는 core `src/**/*.ts` glob이라 `worklet-defaults`·`worklet-order` 두 정적 검사가 모두 덮는다. worklet 3개(`lodT`·`maskSigmaW`·`blurFloorPt`)는 기본 인자가 없고, 참조하는 `LOD_RAMP`·`MIN_BLUR_DEVICE_PX`는 위에 선언돼 TDZ 위험 없음. `useDerivedValue`에서 부르는 것은 `maskSigmaW`뿐이고 worklet이다. `bodyLod`·`bodyEdgePt`·`lodInkLook`은 worklet이 아니지만 JS 스레드 `useMemo`에서만 부른다. Mongmangi 안의 `keyOf`는 worklet 표기가 있고 기본 인자가 없다(앱 쪽은 정적 검사 밖이지만 규칙 준수).
- **앨범 썸네일 캐시 키**(`DreamCardThumb.tsx` keyOf): 메모리 Map(LRU 48)이라 오래된 디스크 캐시 문제 없음. `ptPerPx`는 기기마다 사실상 하나(`width/px` ≈ 1/min(dpr,2)), `px`가 이미 키에 있어 폭증 없음. 꺼짐 키는 `:-`로 고정. 플래그를 런타임에 바꾸면 새 키로 다시 찍고 옛 항목은 LRU로 빠진다. `thumbImage` 호출처는 DreamCardThumb 하나. 오프스크린 `devicePerUnit: 1`도 맞다(이미지 1단위 = 1px).
- **꿈 카드 블러 하한**: 그림자 `W·0.012`·접힘 `W·0.003`. 앨범 썸네일(px 폭 약 176~220)에서도 접힘 0.53~0.66px라 하한이 거의 걸리지 않는다. 화면 카드는 `devicePerUnit = PixelRatio`로 맞다.
- **카드 몸 폭 12.8~16%**: `lod.test.ts` 60조합(비율 2 × 모티프 3 × 획 0~9)으로 고정. 카드 기하는 이번 변경에서 바뀌지 않았고 기존 성질을 검사로 묶은 것이다.
- **과함**: `scripts/a7-*.mjs`(playwright, 루트 devDep)·`docs/app/a7/`(PNG 약 2.3MB)는 번들 밖. `M1Board` view=a7은 기존 개발 보드(`?screen=m1`, App.tsx에서 이미 import)에 분기 하나 추가 — 번들에 새로 들어가는 것은 `handRecords`(core export) 정도. `a7Hands`가 view와 무관하게 마운트마다 12개 계산되는 것은 개발 보드라 무시 가능. A7 범위 package.json 변경 없음(`@mong/contract` 추가는 B0).
- **아트 바이블 v1.4 ↔ thumb-identity 5절 9건**: 1(0-1 원칙)·2(1-1 체형·빗 '왜')·3(1-5 LOD 표·램프·적용 범위·비백 끔)·4(1-3-1 틈 W·닫힘 ≤ 틈/3)·5(12절 W 비례·0.5px 하한)·6(4-1 `stroke-ink-thumb` 4값·대비·송연 확인)·7(1-4 금지 3줄)·8(15절 위험 13)·9(7-4 카드 10%) 모두 반영. 수치(0.10W·0.17W·×2.2·×1.3·×1.8·0.004W·1/3)가 `lod.ts` `LOD_THUMB`와 일치하고 hex 4값은 `lod.test.ts`가 고정. 차이 둘: 제안 9는 "7일차 기준"인데 v1.4는 첫날~열흘 전부(더 엄격, 문제 없음), thumb-identity 4-1의 적용 범위 "공유 카드의 작은 판"이 v1.4에서 "꿈 카드 속 몸은 눈·빗 배율만"으로 좁혀짐(근거 문장 있음).
