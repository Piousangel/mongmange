## 1. 위기 흔적 0 — 직접 재현

### 1-1. 세이브 바이트 동일(재현 통과)
스크래치 스크립트로 core를 직접 돌렸다(문자열은 찍지 않고 개수만 냈다). 사흘 흐름(벼루 → 한 마디 → 연적 → 백그라운드 → 아침, 깰 때마다 백업 회전 포함)을 돌리고, 둘째 날 말만 바꿨다. 글자 수(`chars`)는 실제 글자 수를 썼다.

- 위기 개발 세트 v1.1과 보류 세트 v3에서 `interpretWord`가 곁 대답을 낸 입력은 **885건(ko·en 두 설정)**이다. **885/885건 모두** 아래 세 가지가 '고요' 날과 같았다.
  - KV 전체(본·백업 키 원문)가 바이트까지 같다.
  - 맡겨 두기 업로드 투영(`uploadWords`)이 같다.
  - core 효과 열이 같다.
- 세이브 원문에서 입력 문자열(NFC·NFD)·`x.stay`·`crisis`·`"stay"`를 찾은 결과 **0건**이다.
- 고요 `chars=1`과 `chars=2`도 같다. 글자 수는 저장되지 않는다.
- 시험 `v3-state.test.ts:139`는 `chars: 1`로 고정한 한 사례만 본다. 위 재현으로 일반화가 확인되었다.

## 2. 세이브 v3

- **키 분리:** 확인했다. `mong.v3.save.{main,backup,corrupt}`와 `mong.v3.archive.v2`를 쓴다. v3 쓰기·`clearSaveV3`는 v2 키를 건드리지 않는다(시험과 코드 모두).
- **보관 멱등:** 코드는 맞다. 보관 키가 있으면 덮지 않는다. 다만 이를 지키는 시험이 없다. 변이 M3(덮어쓰기 허용)이 살아남았다 → **M4**.
  - v2 **백업** 키는 보관하지 않는다. 원래 키를 지우지 않으므로 유실은 없다(L2).
- **유실:** v3 모드의 `devReset`(개발 메뉴 '세이브 초기화')은 `clearSave`로 **v2 본도 지운다**. DECISIONS '옛 것은 그대로'와 어긋나지만 개발 메뉴 한정이다(L3).
- **C12·C13(맡겨 두기):** v3 모드에서 `adoptState`가 거부하는 것은 맞다. 하지만 `cloudDeps.local.raw`는 여전히 `SAVE_KEYS.main`(옛 v2 본)을 읽는다. `cloud`와 `conceptV3`를 함께 켜면 지금 키우는 아이가 아니라 옛 v2 본이 올라간다. 복원은 `adopt=false`가 되어 conflict·재시도 경로로 간다 → **M5**. 두 플래그의 상호 배제를 store에서 강제하거나 v3 모드에서 클라우드 행을 숨기는 쪽을 권한다.
- **결정성:** 시험(같은 이벤트 열 = 같은 문자열)과 위 재현 모두 통과했다.
- **검증:** `validateV3`가 `strokeId` 존재를 보지만 이를 지키는 시험이 없다. 변이 M7이 생존했다 → **M4**.
- **앱 store의 v3 경로(`bootV3`·`persist`·`install`·`devRestartV3`)는 시험이 0개**다. `store.test.ts`는 v2 경로만 본다 → **M4**.

## 3. 앱 흐름·안전

**H1 스크린리더·운동 장애 사용자는 먹을 갈 수 없다 → 한 마디를 쓸 수 없다.**
- v3에서는 벼루 300ms 미만 누름이 시트를 연다. 갈기는 길게 누를 때만 된다(`GameHome.tsx` grindHandlers).
- VoiceOver·TalkBack의 두 번 탭은 짧은 누름이라 늘 시트가 열린다.
- 시트의 '먹 갈기' 줄은 안내 문구만 띄우고 닫힌다(`GameApp.tsx` onGrind). 벼루에는 `accessibilityActions`도 없다.
- 그런데 `writeBlock`은 먹이 0칸이면 쓰기를 막는다(`noInk`). 결국 스크린리더 사용자에게는 오늘 한 마디라는 핵심 고리가 닫혀 있다.
- care-rituals 2-1은 '스크린리더에서는 벼루 동작 목록(먹 갈기 · 한 숟갈 · 작은 것)'을 요구한다. 목록 보기(`listView`)와 `assistStroke` 경로도 같다.
- 권고: 시트 '먹 갈기' 줄과 벼루 접근성 동작이 실제로 일정량을 갈게 한다(예: 6칸까지).

**H2 확정하지 않은 글자가 시트 상태에 남는다.**
- `WordSheet`의 `raw`는 확정과 '그만두기·닫기'에서만 비운다.
- 시트는 `visible={wordOpen && kind === 'day'}`로 바깥에서 숨겨진다. 그래도 컴포넌트는 남아 있고(`full &&`로 늘 마운트) `wordOpen`도 true 그대로다.
- 그래서 글을 적다 앱을 떠나 잠·아침이 지나면, 다음 날 홈으로 돌아올 때 시트가 저절로 다시 열리고 **어제 적던 글자가 입력칸에 그대로** 있다. 위기 낱말이라면 그대로 화면에 다시 나타난다.
- 백그라운드로 갈 때 입력칸을 비우지 않는다. 그래서 iOS 앱 전환기 스냅숏(디스크 캐시)에 입력 중인 글자가 찍힌다.
- 권고: `AppState` background와 `visible` false 전이에서 `raw`를 비우고 `wordOpen`을 false로 한다. 백그라운드 진입 시 입력칸을 가리는 것도 검토한다.

**M1 배고픔 낱말에 기쁨 호(QA-3 R4-3 위반).**
- '배고파'·'꼬르륵'·'hungry'·'starving'은 모두 `home.in.meal`이다. `cueOf`는 가족 `home` → `CUE.home`으로 보내고, 이것은 `eyeB: 'joy'`다.
- senses.json 700행은 '배고픔 낱말은 기쁨 호 없이 제자리에서 유저를 본다'고 정한다.
- 사전에 배고픔 낱말을 가르는 표지가 없어 지금 구조로는 가를 수 없다. 사전 표지를 더하거나(PL-1), 그때까지 `home.in.meal` 전체를 기쁨 호 없는 변주로 둔다.

**M2 곁 대답만 드러난다.**
- 스크린리더 알림은 `stay`에만 나간다(`GameApp.tsx` wordAccepted). heart-grain 579·617행은 '대답마다 접근성 알림'을 요구한다.

- 이대로 켜면 화면을 보는 사람이나 듣는 사람 모두 위기 판정을 구별할 수 있다. 저장 흔적은 아니지만 '들킴'(E3)이다.

## 4. 강요·벌 0 / 밤 세기 / 접근성·레이아웃 / 플래그

**강요·벌(D-03):** 대체로 통과다.

**M6 밤 세기 의견(바꿀지는 PM 판정):**

- 선택지:
  - (가) 말을 쓴 깸의 잠은 연적 없이도 센다.
  - (나) 그 밤에 이미 말이 있으면 쓰기를 막는다(벌 쪽이라 비권장).
  - (다) 지금 그대로 두고 '연적으로 재우면 밤이 하나 쌓여요'를 처음 한 번 알린다.

- 참고: Metro를 `CI=1`로 띄우면 파일 감시가 꺼진다. 변이 확인은 서버를 다시 띄워야 반영된다.

**접근성:**
- 사물 라벨('먹 갈기'·'한 마디'·'재우기')과 시트 행 라벨(비활성 사유 포함), 먹물 칸 라벨이 있다.
- 입력칸에는 `accessibilityHint`가 있고 메모는 `accessibilityLiveRegion`이다.
- 모션 줄이기: 대답은 눈·빗만 0.4초로 처리된다. 그러나 **먹 방울 마시기(1.2초 포물선 이동)는 모션 줄이기에서도 그대로 날아간다**(GameHome drop)(L7).

**플래그:**
- `conceptV3 = __DEV__`다. 운영 빌드는 꺼짐이다. `REMOTE_FLAG_KEYS`에 없어 원격으로 켤 수 없다.
- 꺼졌을 때도 `dispatch`가 `write`·`feed`를 무시하고 v2 경로 그대로 간다. verify 전 시험도 통과했다.
- 단, 플래그와 무관하게 바뀐 것이 둘 있다.
  - ① 홈 안내 줄 위치가 `top '30%'` 고정에서 `max(30%, 제목 아래+16)`이 되었다. 긴 이름 제목에서는 v2 화면도 아래로 내려간다(개선 쪽).
  - ② `VerticalTitle`에 `testID`·`onLayout`이 추가되었다.
- '기존 앱 그대로'는 엄밀히는 아니고 '같거나 더 나음'이다.
