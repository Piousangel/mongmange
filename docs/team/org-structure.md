```
 └ 총괄 PM(메인 세션) ─ 로드맵·배정·리뷰 관문·커밋·보고
    ├ 프로덕트 팀 (리드: 프로덕트 리드)
    │   ├ 기획 3   게임·시스템 디자이너 / 콘텐츠·카피(한·영) / UX 리서처·데이터
    │   ├ 디자인 3 크리에이티브 디렉터 / UI·모션 디자이너 / 테크 아티스트
    │   ├ 개발 5   앱(RN) / core sim / 서버 / 네이티브(iOS·Android) / 플랫폼(CI·빌드·배포)
    │   └ QA 3     코드 리뷰어 / 기능·기기·접근성 QA / 보안·개인정보 리뷰어
    └ 마케팅 팀 (리드: 그로스 리드)
        ├ SEO·ASO 2 스토어 최적화 / 웹 SEO(mongmang.ink·프레스킷)
        ├ GEO 1     AI 답변 엔진 노출
        ├ 채널 3    소셜 콘텐츠 제작 / 커뮤니티·크리에이터 / PR·피처드
        └ 분석 1    캠페인 측정·주간 리포트
```

- 역할 22개는 **상시 대기 인원이 아니라 '역할 카드'**다. 일이 생기면 총괄 PM이 역할 카드를 붙여 에이전트를 띄우고, 끝나면 내린다.
- 동시에 도는 에이전트는 **최대 4**(프로덕트 2 + 마케팅 1 + 리뷰 1). 사용량 한도와 파일 충돌을 막는 상한이다.

- 팀 리드 선에서 끝: 그 밖의 모든 안 선택(근거를 DECISIONS에 한 줄).

## 3. 작업 카드 (모든 위임의 양식)

```
역할: {id} · 강도: {낮음~최고} · 팀: 프로덕트/마케팅
0. 착수 전 세 줄 다시 쓰기(OPERATING 7-4)
1. 목표 한 문장 + 왜(세 기둥·지표 중 무엇)
2. 먼저 읽을 정본(경로)
3. 할 일(번호) + 그럴듯한 오답 검사(OPERATING 8-1)
4. 범위 밖: 지금 다른 레인이 잡은 파일·경로
5. 검증: 명령과 합격 기준(제품=pnpm verify, 마케팅=사실 대조표·톤 검사)
6. 산출물 경로 · 커밋 금지(PM만)
7. 보고: 한국어 N줄 + 실행 결과 + 커밋할 파일 + 결정 필요
```

## 4. 레인과 파일 소유권

| 레인 | 동시 | 파일 영역 | 겹칠 때 |
|---|---|---|---|
| 제품-앱 | 1 | apps/mobile, packages/core | 별도 worktree(예: ui/bottom-sheet) |
| 제품-서버 | 1 | apps/server, packages/contract, apps/web-static | 순서 정해 차례로 |
| 마케팅 | 1 | docs/strategy, docs/marketing, 콘텐츠 원본 | web-static은 SE-2가 DV-5에 요청 |
| 리뷰 | 1 | docs/team/reviews (읽기 위주) | 작성 레인과 겹쳐도 됨 |

- **공유 파일**(DECISIONS.md·feature-map.md·roadmap.md)은 각 레인이 '자기 절만' 고치고, PM이 커밋 때 절 단위로 나눠 담는다.
- 총괄 PM은 `.claude/progress.md`에 **레인 표**(누가·무엇을·어느 경로)를 늘 최신으로 둔다.

## 5. 리뷰 관문 (작성자 ≠ 검토자)

| 위험 | 예 | 강도 | 리뷰어 |
|---|---|---|---|
| 최고 | 세이브·결정성, 인증, 삭제, 개인정보, 공개 링크, 결제 | 최고 + 변이 실험 | QA-1 + QA-3 |
| 높음 | 렌더 공용 경로, 네이티브, CI, 정본 문서 | 높음 | QA-1 또는 해당 리드 |
| 보통 | 화면 하나, 콘텐츠 표, 마케팅 계획 | 보통 | 같은 팀 다른 역할 |
| 낮음 | 문구·오타·캡션 | 가볍게 | 짝 리뷰어 |
| 체감 | 귀여움·애착·자랑하고 싶음 | 기계 검사 대신 사람 | DS-1 + 오너(녹화 영상) |

- **마케팅도 관문이 있다**: 밖으로 나가는 글은 ① 사실 대조(제품 정본과 다른 말 0) ② 톤(느낌표·이모지·감정 단정 없음) ③ 개인정보(유저 카드는 허락받은 것만)를 통과해야 게시한다.

## 8. 사용량 관리

- 설계·리뷰·결정성·보안은 가장 강한 모델, 반복 작업(캡처, 표 채우기, 문구 변형)은 가벼운 모델.
- 한도에 걸리면 에이전트는 멈춘 자리를 저장한다. PM은 레인 표에 '멈춤'을 적고, 풀리면 같은 에이전트를 이어서 돌린다(새로 띄우지 않음).
- 동시 4 상한을 넘기지 않는다. 마케팅 레인은 제품이 급할 때 0으로 줄일 수 있다.
