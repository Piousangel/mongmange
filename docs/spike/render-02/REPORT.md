## 0. 질문에 대한 답
1. "아트 바이블의 몽망이가 Skia 2D 실시간 렌더로 `06c` 수준에 닿는가?" — 0일차·밤은 형태·대비 기준으로 닿는다(콩 비율 1.25, 평평한 바닥, 눈 둘 빈자리, 몸에 붙은 E 빗, 번짐 고리, 밤 은회색 몸 + 밝은 테 + 감은 호). 질감은 판정하지 않는다(D-04, 웹).
2. "D-12로 붙였을 때 '몽망이로 보이면서 내가 그었다'가 동시에 되는가?" — **7일차는 아직 아니다**(초판 "절반"을 리뷰 반영해 정정). 7일차 실루엣은 아트 1-4 금지표 "털·톱니 가장자리"(검댕)에 걸린다(7·9절). 회전·이동 부착, 금지 자리 회피, 단일 coverage 이음매 제거는 동작한다. 그러나 ① 같은 마스크·같은 먹색이라 7일차 획이 실루엣 굴곡으로만 읽혀 `02a`의 "획이 몸을 감싼다"가 약하다. ② 금지 자리 ① 상한(45°)이 E 빗 아래 가닥 뿌리(73°)보다 위라 정수리 획이 빗 옆으로 미끄러져 넷째 빗 가닥처럼 읽힌다. ③ 긴 감기 획은 L1~L3 모두 갈고리·꼬리로 읽히고 세 단계 결과가 거의 같다. ②·③은 D-12 수치 결정 필요(10절).

## 1. 몸 — 아트 바이블 수치를 상수로
- `packages/core/src/visual/bodySpec.ts`: 폭:높이 1.25(허용 1.15~1.35), 바닥 현 0.7W, 정수리 곡률 하한 0.35W, 앞 기울기 0.05W / 눈 0.16W·높이 38%·간격 0.42W / 빗 길이비 1:0.9:0.75, 돌출 0.18→0.3W(굵기 0.05→0.066W) / 번짐 고리 1.3W×0.18W @25%, 안내 자국 1.6W @12% / D-12 금지 자리, 돌출 상한, `coreScale(n) = 1 + 0.6(1 − e^(−n/13))`, 팔레트.
- 핵 = 해석적 SDF 하나(`geometry/core.ts`): 타원 ∩ 바닥 평면 smooth-max, 앞 기울기는 전단. CPU(부착)와 GPU(후보 B)가 같은 식. 정수리 곡률 0.536W, 비율·현·기울기는 테스트로 고정.

- E 빗: 가닥마다 몸 안 0.1W에서 출발해 바깥으로 뻗음, 휨 반경 1.1W.
- 7일차 포즈(`day7Records`): 핵 1.25W + 7획, 모두 실제 attachStroke(L2) 통과. 핵 면적 88.0%(기준 ≥75%).

## 3. 세이브 정본 — 입력 점열 (D-13)
- core 함수(React·RN import 없음, 'worklet' + 배열 연산): normalizeRaw·capRaw(512점·6초), simplifyStroke(떨림 제거 → RDP → centripetal Catmull-Rom ≤64), attachStroke, toCorePolar·polarToLocal, strokeSpine·strokeRibbon, coreScale, selectVisual, 세이브 봉투.
- 봉투: `{ schemaVersion: 2, strokes: [{ raw(int16 LE → base64), hasP, attach, drawnAtCoreScale, meshVersion }] }`. 메시는 저장하지 않는다. 부착 판정은 고정 단순화(v1)라 메시를 고쳐도 자리가 안 바뀐다.
- Vitest(리뷰 반영 후 31건 통과 + 알려진 실패 1건)
  - ① 직렬화 왕복 뒤 메시가 같다(같은 프로세스에서 두 번 부른 비교는 JS에서 당연하므로 근거로 쓰지 않는다)
  - ② schema v1 봉투(숫자 배열 raw, taper 없음, meshVersion 1) → 마이그레이션 → meshVersion 2에서 메시 유효·정본 불변. **정정:** 초판의 "v1·v2 끝점 차이 < 0.03W"는 dejitter·RDP·Catmull-Rom이 끝점을 늘 고정해 구조상 항상 통과하는 동어반복이라 **뺐다.**
  - ②-b(신규, 리뷰 2-3 a·b·c): **앵커가 가운데인 획**(앵커 위치를 테스트로 확인)에서 메시 v1 → v2로 바꿔도 (a) v2 스파인이 핵 표면 0.02W 안에 닿고(실측 0.0019W) (b) v1·v2 스파인 하우스도르프 거리 ≤ 0.02W(실측 0.013~0.015W, 0이 아님 = 실제 차이를 잼). 핵 1.08 → 1.25 성장 후에도 같다.
  - 미래 schemaVersion(3) 거부(신규)
  - ③ 24획×150점 = 44,045B(43.0KB) ≤ 64KB(압력 채널 포함, 최악에 가까움)
  - ④ coreScale 1.0→1.1→1.25에서 시작점이 표면 0.02W 안(L1~L3). 단 앵커 = 시작점인 획만 쓴다
  - 그 밖: 아트 수치·눈·빗 길이비·L1 거리 보존·L2 축소·7일차 핵 ≥75%. `coreRadius1(0) > 0.3`(아무것도 지키지 않음)은 지웠다.
- **D-13 확정 조건 근거(정정):** 크기 ③과 마이그레이션 ②+②-b로 **충족**이라 본다. 남은 한계: v1 봉투는 실제로 존재한 적 없는 합성 형식이고(스파이크 01 세이브 없음), 기기 엔진(Hermes vs V8)의 수학 함수 끝자리 차이와 "모르는 meshVersion이면 현재 버전으로 조용히 떨어짐"은 아직 검증하지 않았다(다음 단계).

## 4. 획 입력 — UI 스레드
- RNGH v3 `usePanGesture` worklet에서 점을 SharedValue에 쌓고, 그리는 중 리본은 useDerivedValue에서 core buildRibbon으로 갱신(JS 재렌더 없음). 손을 떼면 runOnJS로 한 번만 정규화·부착·기록.
- 한 획은 대고 뗄 때까지(최대 6초). Catmull-Rom 스파인 + 가중 평균 법선으로 V자 홈 없음.
- 부착: 몸에 가장 가까운 점이 회전 중심. 자리 θ±48°(8° 간격) × 회전 후보를 결정적으로 훑고, 비용(묻힘·뜸·최대 돌출·금지 자리·정수리 솟음·이동량) 최소를 고름. 금지 자리(−25°~+45°, 200°~250°)는 가장 가까운 허용 경계 + 6°로 미끄러짐.
- 부착 애니메이션: 180ms에 60%, 800ms 정착, 번짐 1200ms. 몽망이가 6° 기운 뒤 기쁨 표정.
- L1~L3: `?attach=1|2|3`. L2 = 0.5W 상한 초과 시 균일 축소 + 테이퍼, L3 = 둘레 쪽 휨 30%.
- 압력: RNGH v3 Pan 이벤트에 force/pressure가 없어 비워 둔다.

## 10-2. 리뷰 반영(커밋 전 반드시)
- 테스트: 빗 뿌리 금지 자리 테스트를 `it.fails`(알려진 실패, 10절 1 연결)로 바꿈 — 정본 위반을 통과로 굳히지 않는다. 마이그레이션 동어반복 제거 + ②-b·미래 버전 거부 추가.
- **TDZ 가드:** `packages/core/test/worklet-order.test.ts` — core 소스를 정적으로 읽어 `'worklet'` 함수가 같은 파일에서 **아래에 선언된** 최상위 이름을 참조하면 실패. 위반을 일부러 넣은 파일로 실패하는 것을 확인했다(`a → b`).
- 성능: ① 긋는 중 `live.value = [...pts, p]`(매 이벤트 전체 복사, O(n²)) → `live.modify` 제자리 push + 1px 미만 이동 버림 + 그리는 중 리본은 최대 160점으로 솎기(정본 raw는 전부 저장). ② 부착 애니메이션 중 전 획 재단순화 → 단순화 점열은 기록당 한 번(JS `useMemo`), 리본은 획별 `(핵 크기, 부착 진행)` 키 캐시로 바뀐 획만 다시 만들고, 번짐(fresh)도 그 캐시를 재사용. 웹 재측정(긋는 중 A): DPR2·CPU1× 58.3fps / p95 16.8ms, DPR3·CPU4× 57.1fps / p95 16.8ms. 최대 프레임 83~117ms는 **제스처 시작 직후 한 번**(67ms 1회 관측, 손 뗀 뒤 부착 구간은 30ms 넘는 프레임 없음)이며 원인은 S25에서 다시 본다.
