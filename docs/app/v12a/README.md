## 3. 캡처(이 폴더, 웹 Chromium 2x)

- `grid-day.png`·`grid-night.png`: 행 = 빛 끔(지금) / low 0.5 / mid 0.75 / high 1, 열 = 체형 1.15·1.25·1.35 × 몸 폭 120·64·36pt(체형마다 다른 손 7획·다른 먹).
- `zoom120-{day,night}-body{0,1,2}.png`: 120pt 칸만 세로 띠(같은 네 행).
- 직접 본 결과:
  - 36pt 열은 네 행이 같다(빛 꺼짐 — 의도).
  - 낮: 몸이 거의 검정이라 확산광은 **아주 은은하다**. 120pt에서 왼쪽 위가 살짝 옅고 오른쪽 아래가 약간 깊다. high에서도 밝은 점·광택 띠는 없다. 바닥 그림자가 오른쪽 아래로 길어져 '놓여 있음'이 생긴다. 눈 구멍 위쪽 안 그림자는 120pt에서 가까이 봐야 보이는 정도다.
  - 밤: 풀린 먹 몸이 밝아 빛이 낮보다 잘 보인다. 왼쪽 위 이마가 밝고 오른쪽 아래로 넓게 어두워진다. 수면 위 그림자가 몸을 띄워 준다. 조약돌 광택으로 읽히지는 않았다(작성자 판단, 편향 있음).

## 4. 성능

- 프레임당 추가 작업(빛 켠 몸 하나): ① 런타임 셰이더 사각 1번(몸 경계 상자 3.4W 정사각, 픽셀당 ALU 약 20회 — 노이즈·반복문 없음, 새 saveLayer 없음, 기존 바깥 레이어 안에 `srcATop`) ② 흐린 타원 2개(해석적 도형의 블러 마스크 — Skia가 캐시) ③ 흐린 눈 경로 1번(`dstOver`). 몸 칠은 이미 '닫힘(팽창·침식) + 블러 + 색 행렬 여러 겹' 이미지 필터 그래프라, 이것보다 한 자릿수 가볍다고 본다(추정).
- 웹 측정(`perf.json`, headless Chromium·ANGLE 소프트웨어 래스터, 120pt 몸을 매 프레임 흔들어 다시 그림, 끔·켬 번갈아 3번): 12마리 끔 146.8~154.8ms / 켬 154.7~163.9ms(평균 +약 6%), 36마리 끔 413.5~446.8ms / 켬 413.3~430.0ms(차이 없음, 잡음 안). **이 기계는 측정 중 다른 작업으로 부하가 컸다(load 30 안팎)** — 절대값은 의미가 없고 '눈에 띄는 증가 없음'까지만 말할 수 있다.
- 리뷰 지적대로 `perf.json`은 소프트웨어 래스터 rAF 간격이라 **GPU 채움 비용에 대해서는 아무것도 말하지 않는다**(근거로 인용하지 않는다).
- 리뷰 반영 뒤 줄인 것: 셰이더 사각 = 몸 경계 상자(핵 + 획·빗 리본 + 번짐 여유). 7획 몸 기준 예전 3.4W 정사각(11.6W²)에서 대략 1.8W × 1.5W(약 2.7W²)로 — 채움 면적 약 1/4(추정, 획 길이에 따라 다름). 바닥 그림자 변환은 모듈 최상위 worklet(렌더마다 매퍼 재시작 없음).
- **V20 실기기 측정 조건**(roadmap V20 비고에도 적음): ① 기기 = Mali-G52/G57급 중급 하단 Android + 3x 기기 1 ② 장면 = 홈 한 마리 + **48pt 넘는 몸이 여러 마리 동시에 보이는 화면**(화첩·두루마리 큰 칸 등) ③ 지표 = fps가 아니라 **GPU 프레임 시간 16.6ms 안**, 빛 끔·켬 차이 ≤ 1.5ms, 열 쓰로틀 5분 뒤 다시 ④ 넘으면 정지 중 빛 레이어 `Picture` 캐시. ⑤ 같은 자리에서 아트 판정: **밤 빛 방향 그림자(55%)가 번짐 고리(먹 이름표)보다 먼저 읽히는지**(그러면 40%대로) — 리뷰 아트 6번.
