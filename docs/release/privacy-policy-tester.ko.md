## 1. 테스트 빌드가 휴대폰 밖으로 보내는 것

이 테스트 빌드가 운영자 서버나 다른 회사로 보내는 정보는 1-1과 1-2뿐입니다. 이용 통계, 링크로 공유, 클라우드 보관(맡겨 두기)은 이 빌드에서 꺼져 있어 계정이 만들어지지 않고 게임 기록이 서버로 가지 않습니다. 기능을 더 켜는 업데이트를 내기 전에 이 방침을 먼저 고치고 앱 안에서 알립니다.

### 1-1. 앱 업데이트 확인 (모든 테스터)

- 앱은 오류 수정을 빠르게 반영하려고 **두 번째 실행부터 기기 날짜로 하루 한 번** 운영자의 업데이트 서버(Google Cloud Run, 대한민국 서울 리전)에 새 버전이 있는지 묻습니다. 첫 실행에는 묻지 않습니다. 요청은 Google의 웹 전송 서비스(Firebase Hosting, 전 세계 네트워크)를 지나 서울의 서버에 닿습니다.
- 예외: 앱이 시작하자마자 오류로 멈추면(첫 실행 포함) 업데이트 장치가 고친 버전이 있는지 한 번 찾아보고, 앱이 연달아 두 번 비정상적으로 끝나면 하루 한 번 제한을 건너뛰고 바로 묻습니다.
- 요청에 실리는 것: 플랫폼, 앱 실행 환경 판·업데이트 채널, 지금 쓰고 있는 업데이트와 앱에 들어 있던 업데이트의 식별자(같은 버전을 쓰는 모든 테스터가 같은 값), IP 주소와 통신에 필요한 기본 정보(User-Agent 등).
- 보내지 않는 것: 업데이트 장치가 표준으로 싣는 설치별 무작위 식별자, 실패한 업데이트의 식별자, 앱을 멈춘 오류 내용은 모든 테스터에게 같은 고정값(또는 빈 값)으로 바꿔 보냅니다. 그래서 업데이트 확인 요청으로 설치나 기기를 구별할 수 없습니다.
- 운영자는 맞는 업데이트를 고르는 데 필요한 값만 그 순간 쓰고, 데이터베이스와 운영자의 서버 기록(앱 로그)에 남기지 않습니다. 과도한 요청을 막으려고 IP 주소(IPv6는 앞부분 64비트)를 서버 메모리에서 약 1분 동안 세는 데만 씁니다.
- 클라우드 사업자(Google Cloud Run)는 요청마다 IP 주소·User-Agent·요청 경로·시각 등을 담은 접속 기록을 만들지만, 운영자는 이 기록을 받아 보관하지 않도록 설정했습니다. 장애를 조사할 때만 잠시 받을 수 있으며, 그때 받은 기록은 최대 7일 뒤 지워집니다. 운영자 서버의 기록(앱 로그·오류 로그)은 7일 보관하며, 여기에는 IP 주소와 User-Agent를 적지 않습니다.
- 업데이트 요청이 지나는 Firebase Hosting의 요청 기록은 운영자의 로그로 보내는 기능을 켜지 않아 운영자가 받지 않습니다. Google이 서비스 운영을 위해 따로 남기는 기록은 Google 정책에 따릅니다.
- 받은 업데이트는 다음에 앱을 새로 시작할 때 적용되며, 앱을 쓰는 도중에 바뀌지 않습니다.

### 1-2. 손글씨 인식 (모든 테스터)

- '한 마디'의 글씨는 Google의 ML Kit 손글씨 인식(Digital Ink Recognition)으로 **기기 안에서** 읽습니다. 처음 쓸 때 언어별 인식 모델(약 20MB)을 Google 서버에서 내려받으며, 이때 IP 주소가 쓰입니다.
- **쓴 글씨(획)와 인식 결과는 Google이나 운영자에게 보내지 않습니다.** 모델을 내려받지 못하면 키보드로 쓸 수 있습니다.
- 손글씨 인식 기능은 동작하면서 Google에 진단 정보를 보냅니다: 기기 정보(제조사·모델·운영체제 버전과 빌드, 쓸 수 있는 연산 가속기), 앱 정보(패키지 이름·앱 버전), 설치마다 만든 식별자, 성능 값(처리 시간 등), 기능 설정 값, 설정한 인식 언어, 입력·출력 크기, 기능 판, 사건 종류, 오류 코드. Google은 이 정보를 ML Kit의 진단과 사용 분석에 씁니다. 운영자는 이 정보를 받거나 보지 않습니다. 자세한 내용은 Google의 ML Kit 데이터 공개 문서(https://developers.google.com/ml-kit/android-data-disclosure)에 있습니다.
