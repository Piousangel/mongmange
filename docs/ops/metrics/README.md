# 집계 지표 운영 규칙 (B0, 2026-11-20)

정본: architecture.md v2.1 3-6·5-2·5-5, 처리방침 3-1, B0 리뷰(`docs/team/reviews/2026-11-20-b0-review.md`) I2·I5.

## 1. 누가 무엇을 보나

| 대상 | 누가 | 방법 |
|---|---|---|
| 원표 `app.metric_daily` | **서비스 롤(표 소유자 `prisma`)만** | 판정 SQL(`*.sql`)을 그 롤로 돌린다. 사람이 원표를 직접 열람·내보내기하지 않는다 |
| 조회 뷰 `app.metric_daily_k5` | 조회 롤 `metrics_reader`(B6에서 만든다) | 칸 수(count) **5 미만은 보이지 않는다**. 대시보드는 이 뷰만 읽는다 |

- **원표 내보내기 금지**: CSV·스프레드시트·스크린숏으로 원표를 옮기지 않는다. 판정 보고에는 판정 SQL의 결과(비율·구간)만 싣는다.
- **테스터 기간(소프트런칭 전, 비공개 테스트) 동안 원표를 보지 않는다.** 테스터는 운영자가 아는 사람이라, 설치일·플랫폼·언어로 한 사람 칸을 되짚을 수 있다(리뷰 I2). 이 기간에는 핑이 켜져 있어도(켜지 않는 것이 기본) 조회 뷰·판정 SQL을 돌리지 않는다.
- 90일 지난 원표는 월 합계로 말고 지운다(처리방침 6절, `pg_cron` — B6 관문).

## 2. 오염 방지와 한계

- 서버는 **알려진 출시 판**(`METRIC_APP_VERSIONS`)만 받고, 인스턴스당 하루 새 칸 수에 상한(`METRIC_NEW_CELLS_PER_DAY`, 기본 2만)을 둔다. 넘으면 버리고 개수만 로그에 남긴다. 새 판을 낼 때 `METRIC_APP_VERSIONS`를 먼저 늘린다.
- 판정 전에 `monotonic-check.sql`을 돌려, n일째 열기나 평생 한 번 사건이 설치일 열기보다 많은 코호트 묶음은 판정에서 뺀다. 설치일 열기는 스토어 콘솔 설치 수 × 1.2와 대조한다(정본 3-6).
- **한계**: 레이트 리밋(IP 접두당 분당 20)과 하루 새 칸 상한은 **인스턴스 메모리**라 인스턴스 수만큼 느슨해진다(max 3이면 3배). IPv6는 /64마다 따로 센다. 인증 없는 집계라 개수 조작을 완전히 막지 못한다 — 단조 검사·설치 수 대조로 판정에서 걸러 낸다.
- 중복 대 유실: 서버는 요청 안 쓰기를 최대 1.5초만 기다리고 204를 돌려주며, 앱은 시간 초과(10초)를 '보냄'으로 본다(다시 보내지 않음). 그래서 오류 쪽은 중복이 아니라 **유실**이고, 리텐션이 낮게(보수 방향) 나온다. 판정 보고에 이 편향을 적는다.
- `moon` 차원은 core 달 위상 함수가 연결되기 전에는 늘 '0'이다. 그 날짜 전의 `moon`은 판정·참고에 쓰지 않는다.
