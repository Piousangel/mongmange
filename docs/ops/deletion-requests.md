# 삭제 요청 절차 — 사용자 문의 → 처리 (B5)

- 정본: `docs/design/server-v1/architecture.md` v2.2 3-8 '삭제(파기) 절차', 처리방침 `docs/release/privacy-policy.ko.md` 4·6·12·17절. 결정: `DECISIONS.md` 'B2 맡겨 두기 구현 결정'(웹 삭제 즉시)·'B5 안전 장치 구현 결정'(운영자 삭제 요청).
- 원칙: **이용자가 직접 지우는 길이 먼저다.** 운영자는 글귀를 받지 않고, 운영자 삭제는 본인 확인이 끝난 예외에만 쓴다.

## 1. 문의가 오면 — 무엇을 원하나로 가른다

| 원하는 것 | 안내(답장 문구 요지) | 운영자가 할 일 |
|---|---|---|
| 서버에 맡긴 것 모두 지우기(앱이 있음) | 공방 노트 → '서버에 맡긴 것 지우기'. 바로 처리되고 영수증이 나온다 | 없음 |
| 앱 없이 지우기(글귀가 있음) | `https://mongmang.ink/delete`에 인장 코드와 되찾기 글귀. **글귀를 메일에 적지 말 것** | 없음 |
| 메일에 글귀를 적어 보냄 | 처리하지 않는다. 위 웹 페이지를 안내하고 '받은 메일은 지웠다'고 답한다 | **그 메일을 받은편지함·휴지통에서 지운다**(글귀 평문이 우리 메일함에 남지 않게) |
| 공개 페이지만 멈추기 | 앱에서 '링크로 공유' 끄기 | 없음 |
| 이름만 숨기기 | 앱에서 이름 공개 끄기 → '다시 만들기' | 없음 |
| 남의 페이지가 나에 관한 것(실명·사진처럼 보이는 모양 등) | 페이지의 '알리기'로 신고하거나 메일로 링크를 보내 달라고 한다 | 신고 런북(`docs/ops/moderation/README.md`)으로 판단 — 이름 가리기(`05`)·확정 삭제(`03`) |
| 만 14세 미만 아동의 정보라는 보호자 연락(처리방침 4절 '지체 없이 지웁니다') | 인장 코드(링크 주소의 8자)를 받는다. 앱이 있으면 앱에서 지우는 길을 먼저 안내 | 즉시 `03-confirm.sql`(공개 내리기) → 아래 2절(72시간 대기 삭제) |
| 글귀도 앱도 없음(본인 요청) | 본인 확인 수단이 없어 처리하지 못할 수 있다. 앱을 2년 열지 않으면 자동 정리된다(처리방침 6·12절) | 원칙적으로 처리하지 않는다 — 본인 확인 방법은 **법률 검토 결과**(처리방침 12절 [법률 검토 후 기입])를 따른다 |
| 열람·정정 | 서버에는 이름·연락처가 없고, 게임 기록은 앱에서 보인다 | 법률 검토 결과에 따라 |

## 2. 운영자 삭제(예외) — 요청 → 72시간 대기 → 실행 (`08-delete-account.sql`, 취소 `08b-cancel-deletion.sql`)

**인장 코드(링크 주소의 8자)는 링크에 공개된 값이라 신원 근거가 아니다.** 아무나 '내 아이 것'이라며 남의 코드를 보낼 수 있다(B5 리뷰 H1). 그래서:

- **즉시 할 수 있는 조치는 공개 내리기뿐이다**: `03-confirm.sql`(확정 숨김 — 파일은 지워지지만 계정·세이브는 그대로, 링크는 `07-reopen.sql`로 다시 켤 수 있다). 만 14세 미만 아동이라는 연락이면 이것부터 한다.
- 계정 삭제는 아래 경우에만, 본인·보호자 확인 방법은 **법률 검토 결정 대기**(`docs/release/legal-review-questions.md` B-14 ③). 결정 전에는 근거가 분명한 경우(법령에 따른 요구 등)에만 쓴다.
  - 근거 유형 `guardian`(보호자 — 만 14세 미만) · `legal`(법령에 따른 요구) · `self`(법률 검토로 정한 본인 확인을 마친 요청)

1. 요청을 접수 번호로 적는다(메일함 밖 기록에는 코드·이메일을 적지 않는다). `01-queue.sql`·접수 메일로 대상 코드를 한 번 더 대조한다.
2. Studio에서 `08-delete-account.sql`의 `'________'`를 인장 코드로, 두 번째 값을 근거 유형으로 바꿔 실행 → `scheduled`.
   - 기록(`admin_actions`)에는 `delete_request`·근거 유형·운영자(DB 로그인)만 남는다 — 코드 없음.
3. **72시간 대기**: 주인 앱은 `GET /creature`의 `deletionPendingUntil`로 '곧 지워져요'를 알린다(문구 키 `account.deletionPending`, 문구는 작가 몫). 주인이 연락해 오거나 잘못 접수했으면 `08b-cancel-deletion.sql`로 취소(기록 `delete_cancel`, 코드 없음).
4. 72시간이 지나면 서버 작업 `moderation`(5분마다)이 앱 안 삭제와 **같은 연쇄**로 지운다: 게임 기록·이전 본·공개 페이지와 파일(세 버킷)·링크 통계·로그인(Supabase Auth)·연령 확인 기록, 백업 복원 대비 표지 7일(3-8 '백업'). 그 코드의 열린 신고는 `account_deleted`로 닫힌다.
5. 확인: `select completed_at, channel, kind, items from app.deletion_log order by id desc limit 1;` → `channel = email`, `kind = user_request`, `completed_at`이 찼으면 끝. `/m/<코드>`가 '사라진 링크'.
6. 답장: '지웠다 + 백업 속 사본은 7일 뒤 소멸'(처리방침 6절). 그 뒤 **요청 메일을 처리방침 6절의 기간 안에 지운다**([기간 — 오너 결정]).

- 되돌림: 실행 전(72시간 안)에는 `08b`, 실행 뒤에는 **없다**.
- 남는 것: 그 코드의 신고 기록(1년, 처리방침 6절 '신고 기록'), 식별자 없는 집계, 백업 속 사본(7일).
