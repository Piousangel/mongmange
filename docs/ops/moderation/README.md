# 신고·숨김 운영 런북 (B5)

- 정본: `docs/design/server-v1/architecture.md` v2.2 3-8 '신고 → 자동 숨김'·3-9 상태 전이·3-12 관리 도구·3-5-2 '이름 가리기'. 결정: `DECISIONS.md` 'B5 안전 장치 구현 결정'.
- **관리 API는 없다.** 운영자는 Supabase Studio(운영 프로젝트 `mong-prod`) → SQL 편집기에서 이 폴더의 스니펫을 붙여 넣고 `'________'`만 인장 코드로 바꿔 실행한다. 스니펫은 서버 시험(`apps/server/test/b5.db.test.ts`)이 **파일 그대로** 실행해 검증한다 — 스니펫을 고치면 시험도 돈다.
- 파일을 옮기거나 지우는 일은 SQL이 하지 않는다. SQL은 대기 행을 적고, 서버의 Cloud Scheduler 작업 **`moderation`(5분마다)**이 처리한다. 바로 처리하려면 Cloud Scheduler 화면에서 `moderation` → '지금 실행'.

## 1. 운영 SLA

| 무엇 | 언제 | 누가 |
|---|---|---|
| 자동 숨김(격리) | 서로 다른 3명(IP 접두 — IPv4 /32·**IPv6 /48**)이 7일 창 안에 신고한 **그 요청 안에서** | 서버 |
| 숨기지 않고 대기 목록에만(held) | `disabled` 자동 숨김 꺼짐(**운영 기본 — B6 XFF 실측 전**, env `REPORT_AUTO_HIDE`) · `immune` 최근 7일 안에 복원된 대상 · `breaker` 서비스 전체 최근 1시간 자동 숨김 5건(env `REPORT_AUTO_HIDE_PER_HOUR`) | 서버 → 오너 |
| 운영자 확인 | 숨김 뒤 **7일 안**(`01-queue.sql`의 `decide_by`). held는 아직 공개 중이라 먼저 본다 | 오너 |
| 결정이 없을 때 | 격리 30일 → **복원**이 기본값(`auto_restore` 기록, B5 리뷰 H2 — 악성 신고가 운영자 부재로 영구 삭제가 되지 않게). 그 뒤 7일 면역 | 서버(`moderation`) |
| 알림 | warn `report_auto_hidden`(숨김)·`report_held`(대기 목록), error `report_auto_hidden_burst`(차단기)·`moderation_sla`(격리 6일 넘김) — 모두 개수만·코드 없음. B6에서 Cloud Logging 알림에 건다 | 서버 |

- '즉시'의 정확한 뜻: 신고 요청 안에서 페이지 상태가 바뀌고 공개 파일이 격리 버킷으로 옮겨진다. `/m` HTML은 CDN 무효화(1분 묶음, 실패하면 `s-maxage` 5분)로, 이미 받은 공개 파일은 Smart CDN 무효화(약 60초, B6 실측)로 사라진다. 이미 퍼진 메신저 미리보기 카드와 브라우저 캐시는 범위 밖(아래 4절).

## 2. 하루 한 번(또는 알림을 받았을 때)

1. `01-queue.sql` 실행. 맨 위가 숨겨진 것(`auto_hidden`), 그 아래가 문턱 전 열린 신고.
2. 숨겨진 것마다 `files` 경로를 Studio → Storage → `quarantine` 버킷에서 연다(포스터·루프·snap.json). **[확인 필요: 비공개 버킷 미리보기 — 안 되면 서명 URL 5분]**. `reasons`(사유 코드별 수)·`shown_name`(실린 이름)·`reports_1y`(재발)를 본다.
3. 하나를 고른다. 두 번째 값(메모)에는 **판단 근거만** 적는다(개인정보·이메일 금지).

| 판단 | 스니펫 | 결과 |
|---|---|---|
| 문제없음 | `02-restore.sql` | 5분 안 live(같은 판 그대로). 주인이 격리 중에 링크를 껐으면 되살리지 않고 off |
| 모양이 문제 | `03-confirm.sql` | 격리본 삭제, `removed` — 주인의 다시 만들기 409 |
| 이름만 문제(실명·연락처·괴롭힘) | `05-mask-name.sql` → 격리 중이었으면 이어서 `02-restore.sql` | 즉시 HTML·OG 제목에서 이름 0, og:image는 포스터. 5분 안 이름 없는 새 판으로 바뀌고 옛 파일 삭제. 주인은 이름 공개를 다시 켤 수 없음(409) |
| 문턱 전 신고가 장난 | `04-dismiss.sql` | 그 신고의 소금·신고자 키 즉시 삭제 |
| 문턱 전이지만 바로 내려야 함 | `03-confirm.sql`(live 판도 내린다) | 위와 같음 |

4. `09-audit-log.sql`로 기록이 남았는지 본다.

되돌리기(B5 리뷰 4절) — **비가역 둘(`03`·`08`)은 실행 전에 `01-queue`로 대상 코드를 한 번 더 대조한다.**

| 실행한 것 | 되돌리는 법 |
|---|---|
| `02` 복원 | `03` 확정 |
| `03` 확정 | `07` reopen(링크를 다시 켤 수 있게만 — **파일은 영구 손실**, 주인이 다시 만든다) |
| `04` 기각 | 없음(신고자가 다시 신고) |
| `05` 이름 가리기 | `06` 해제(이름 공개는 꺼진 채 — 주인이 다시 켜고 다시 만든다) |
| `08` 계정 삭제 요청 | 72시간 안 `08b` 취소, 실행 뒤에는 **없음** |

## 3. 데이터가 남는 기간(처리방침 3-6·5·6절과 같은 값 — 바꾸면 처리방침도)

| 데이터 | 기간 | 지우는 것 |
|---|---|---|
| 신고 소금·신고자 키(HMAC(소금, IP 접두)) | 숨김·운영 처리 때 바로, 아니면 창 7일(작업 주기 5분 + 여유 10분이라 7일을 넘지 않음) | 트리거 `reports_close_hits` + `app.expire_reports` |
| 신고 행(코드·사유 수·신고자 수) | 1년 | `app.expire_reports` |
| 운영 기록 `admin_actions` | 1년 | `app.expire_reports` |
| 격리본 | 결정 때까지, 최대 30일(그 뒤 복원) | `app.expire_quarantine` + 대기열 |
| 운영자 계정 삭제 요청 | 72시간 대기 뒤 실행 | `moderation` |

- 평문 IP는 어떤 표에도 없다. 신고 횟수 제한(IP 접두당 5/시간)은 서버 메모리에서만 세고, 창이 끝나면 10초 안에 메모리에서도 지운다.

## 3-1. B6에서 확인할 것

- **Studio 실행 롤**: 운영 함수 ACL은 소유자(마이그레이션 롤 `prisma`)뿐이다. Supabase Studio가 접속하는 롤(`postgres`)이 `prisma` 멤버인지(EXECUTE)·RLS를 넘는지 운영 프로젝트에서 `select app.dismiss_report('________')`류로 확인한다(실패하면 권한 오류·'없습니다'로 멈춘다 — B5 리뷰 M4). 필요하면 운영자 롤을 정해 `GRANT EXECUTE`.
- **XFF 실측 전에는 `REPORT_AUTO_HIDE`를 켜지 않는다**(운영 기본 꺼짐). hops가 실제보다 크면 한 사람이 요청 3번으로 아무 페이지나 숨긴다.
- **Firebase `/m/**` rewrite가 `Sec-Fetch-Site`·`Origin` 머리글을 Cloud Run까지 넘기는지** curl·브라우저로 확인(신고 폼 같은 출처 판정의 1차 근거).
- Scheduler `moderation` 5분·OIDC, 로그 알림 넷(위 1절).

## 4. 카카오톡 미리보기 캐시 초기화(확정 삭제·이름 가리기 뒤)

- 이미 공유된 카카오톡 미리보기 카드는 카카오 서버에 남는다. 카카오 개발자 사이트의 '공유 디버거'에 `https://mongmang.ink/m/<코드>`를 넣고 캐시 초기화 **[확인 필요: 앱 등록·권한]**. X·iMessage 등은 통제 밖(처리방침 5절).

## 5. 하지 않는 것

- 세이브 열람·사용자 검색·IP 조회 — 그런 함수가 없다.
- 신고자에게 결과 알리기 — 신고자를 알 수 없다(가명 값만, 7일).
- 계정 삭제는 이 런북이 아니라 `docs/ops/deletion-requests.md`(`08-delete-account.sql`은 그 절차에서만).
