## 1. 꼭 지키는 원칙 (카드마다 점검)

카드는 아래 여섯 줄을 하나라도 어기면 점수를 매기지 않고 **버림**으로 보낸다. 고쳐서 지킬 수 있으면 고친 안을 카드에 적는다.

| # | 원칙 | 근거 |
|---|---|---|
| P1 | **벌·강요·죄책감 없음.** 안 해도 잃는 것이 0이다. 마름·크기·색·성장·정이 그 콘텐츠와 무관하다. 연속 기록·끊김·"며칠째" 표시 금지. 관계 문구 알림 금지 | D-03(확정)과 보강 ①~⑤ |
| P2 | **사물은 셋(붓·벼루·연적).** 화면에 누르는 사물을 늘리지 않는다. 새 기능의 입구는 기존 사물의 길게 누르기, 한지 위 제스처, 공방 노트(목록 UI) 중 하나다 | D-08 |
| P3 | **하루 필수 행동은 한 마디뿐.** 진행(밤·성장)이 걸린 행동을 새로 만들지 않는다. 새 콘텐츠는 모두 선택이다 | D-26, systems 1.4 |
| P4 | **숫자·점수·채점 없음.** 말결·가족·강도·횟수·비율을 화면에 보이지 않는다. 맞히기도 '오답' 반응이 없다 | heart-grain 5-5 |
| P5 | **공유물에는 세상 가족만, 글자는 기본 숨김.** 마음 가족(들뜸·포근·뾰족·가라앉음)이 공유물에서 읽히면 안 된다. 쓴 말이 보이려면 유저가 '쓴 말 보이기'를 켜고 B5를 지나야 한다. 곁 대답 날은 흔적 0 | heart-grain 1·9절 |
| P6 | **남에게 자유 글·자유 그림을 전달하지 않는다.** 소셜은 비동기·프리셋·친구 그래프 없음. 한정 획득 없음(절기 것은 해마다 다시 온다). 결제·뽑기로 '키운 결과'를 팔지 않는다 | D-05, D-03 보강 ③, 05 해부 4-2 |

- 같이 보는 것: 몽망이는 말하지 않는다(말풍선 금지, 관찰자 3인칭 자막만 — D-02·D-20). 런타임 LLM 없음(D-02 개정). 접근성 대체 입력(D-08) 하나를 반드시 적는다.

## 2. 카드 양식

```
### I-000 이름
- 한 줄: (유저가 무엇을 하고, 몽망이가 어떻게 되는지 한 문장)
- 28밤 중 언제: 1~7 / 8~14 / 15~21 / 22~28 / 아무 때
- 렌즈: (아래 4절의 렌즈 중 하나 이상)
- 자유도 종류: 표현 · 선택 · 탐험 · 창작 · 관계 (해당하는 것)
- 유저가 하는 것: (입구 → 제스처 → 결과, 3줄 이내)
- 몽망이 반응: (몸짓·빗·번짐·소리. 3초 대답 문법을 깨지 않는지)
- 개인화 연결: 말결(가족·세상 가족) / 타고남(체형·빗 모양) / 먹 / 성향 4축 / 정 중 무엇과 이어지나
- 지키는 원칙: P1~P6 점검 한 줄씩(어기는 것이 있으면 고친 안)
- 접근성 대체: (D-08)
- 비용: 앱 n일 · 아트 n일 (· 작가·소리 n일) [팀 추정]
- 위험:
- 중복 확인: (겹치는 기존 안 / 정본 위치, 없으면 '없음')
- 점수: 기쁨 n · 자유도 n · 독창성 n · 자랑거리 n · 비용 역수 n · 안전 n = 합 n/30
- 반론:
  - 디자이너:
  - 작가:
  - 리서처:
  - 라이브옵스:
- 상태: 새
```

## 3. 점수 기준 (각 1~5)

| 기준 | 5 | 3 | 1 |
|---|---|---|---|
| **기쁨** | 해 보면 웃음이 나오거나 몽망이가 사랑스러워진다 | 무난하다 | 일 같다 |
| **자유도** | 유저가 직접 만들거나 고른 것이 결과의 주연이다(창작) | 고르는 칸이 몇 개 있다(선택) | 정해진 결과를 받기만 한다 |
| **독창성** | 먹·한지·글씨 세계관이 아니면 나올 수 없다. 경쟁작에 없는 동사다 | 장르에 흔한 것을 세계관 옷으로 갈아입혔다 | 경쟁작 패턴 그대로다 |
| **자랑거리** | 한 장이나 짧은 영상으로 "나도 해 볼까"가 생긴다(공유물 규칙 P5 안에서) | 앱 안에서만 뿌듯하다 | 보여 줄 것이 없다 |
| **비용 역수** | 앱+아트 합 1일 이하 | 2.5~4일 | 6일 초과 (4=1~2.5일, 2=4~6일) |
| **안전** | 원칙 위반 가능성이 구조적으로 0이다 | 규칙 한두 줄로 막아야 한다 | 운영·검수 사람 손이 계속 든다 |

- 합은 30점 만점이다. **동점이면 자유도 → 독창성 → 비용 역수 순으로 가른다**(오너가 자유도를 맨 앞에 둠).
- 점수는 회차 토론에서 네 사람이 합의한 값 하나만 적는다. 다시 매기면 옛 점수를 지우지 말고 `~~22~~ 24 (n회차)`처럼 남긴다.

## 4. 회차 운영

### 4-1. 한 회차의 순서

1. **렌즈 확인**: 이번 회차 렌즈(4-2 순서)와 지난 회차의 '다음 회차로 넘김' 목록을 읽는다.
2. **정본 다시 읽기**: 지난 회차 뒤에 바뀐 DECISIONS·concept-v3 문서가 있으면 먼저 읽는다(특히 D-26 세부, care-rituals, rollout-plan 자르는 순서).
3. **카드 쓰기**: 회차당 새 카드 **5~10장**(첫 회차만 15~20장). 이레 네 구간이 한쪽으로 쏠리지 않게 한다.
4. **중복 거르기**(4-3).
5. **반론 달기**: 카드마다 네 관점이 한 줄씩. 칭찬 반론은 쓰지 않는다. 반론이 카드를 고치면 고친 안을 카드 본문에 반영하고 반론 줄 끝에 `→ 반영`을 붙인다.
6. **점수·상태 바꾸기**(5절).
7. **회차 기록**: `backlog.md` 끝에 회차 요약(렌즈, 새 카드 수, 상태가 바뀐 카드, 상위 5, 넘길 질문)을 적는다.
8. **슬랙 보고**: #mongmange에 부모 메시지 하나 — `[아이디어] 28밤 콘텐츠 n회차 · 카드 N장 · 상위 5 …` + 상위 5를 한 줄씩. 스레드에 세부를 붙이지 않는다(파일 경로만).

### 4-2. 렌즈 순서 (회차마다 하나씩 돌린다)

| 순서 | 렌즈 | 묻는 것 |
|---|---|---|
| 0 | (1회차) 전체 훑기 | 열 렌즈 모두에서 한두 장씩 |
| 1 | 하루 의례 사이 틈 | 갈고·쓰고·내려놓기 사이의 빈 시간에 할 것 |
| 2 | 이레마다 이벤트 | 7·14·21·28번째 아침에 무엇이 달라지나 |
| 3 | 계절·절기 | 24절기·세시·실제 보름. 해마다 다시 오는 것 |
| 4 | 수집·꾸미기 | 칸이 차는 것(혼자 채우는 도감), 걸어 두는 것 |
| 5 | 함께 하는 놀이·미니게임 | 몽망이와 주고받는 짧은 놀이(점수 없이) |
| 6 | 몽망이 쪽에서 먼저 거는 것 | 몽망이가 먼저 내미는 것(말 없이) |
| 7 | 기억·회상 | 지난 말·글씨·밤이 돌아오는 방식 |
| 8 | 28밤 뒤 | 완성된 아이와의 관계, 다음 방울, 세대 |
| 9 | 친구·공유 | 비동기·프리셋·자유 글 없음 안에서 |
| 10 | 감각(소리·진동·빛) | 허밍·햅틱·빛·물소리 |

- 10번 다음은 1번으로 돌아간다. 하루에 회차가 여러 번이면 렌즈도 그만큼 넘긴다.
- 한 렌즈를 두 바퀴째 돌 때는 지난 바퀴의 '채택 후보'를 먼저 읽고 그 빈자리를 찾는다.

### 4-3. 중복 거르기

- **같은 아이디어**: 유저가 하는 동사와 결과물이 같으면 같은 아이디어다(이름·테마만 다르면 같다). 새 카드를 쓰지 말고 기존 카드의 `변형` 줄에 덧붙인다.
- **합치기**: 같은 회차 안에서 겹치면 하나로 합치고, 합친 사실을 회차 기록에 적는다.
- **기존 계획과 겹침**: 아래 '이미 있는 것'과 같으면 카드를 쓰지 않는다. 그것을 키우는 안이면 카드를 쓰되 `중복 확인` 줄에 "○○의 확장"이라고 밝힌다.

**이미 있는 것(정본·계획에 들어 있음 — 새 카드로 쓰지 않음)**

| 묶음 | 항목 | 어디 |
|---|---|---|
| 하루 의례 | 먹 갈기(먹 양·진하기)·한 마디·마시기 → 3초 대답·연적 내려놓기·연습지·붓 거꾸로 쓸어 지우기 | concept-review 3-1, D-26 |

## 5. 상태

```
새 → 검토 → 채택 후보 → 로드맵
             ↘ 보류      ↘ (PM이 안 받으면) 보류
       ↘ 버림
```

| 상태 | 들어가는 조건 | 누가 |
|---|---|---|
| **새** | 카드를 쓰고 반론 네 줄과 점수를 붙였다 | 기획실 |
| **검토** | 다음 회차에서 한 사람 이상이 "더 볼 만하다"고 했고, 반론을 반영해 카드를 한 번 고쳤다 | 기획실 |
| **채택 후보** | 점수 합 **22 이상**, 원칙 P1~P6 위반 0, 반론 중 '막는 반론'(구조적으로 원칙을 어김)이 없음, 비용·위험이 숫자로 적혀 있음. 네 사람 중 셋 이상 찬성 | 기획실 |
| **로드맵** | 총괄 PM이 DECISIONS·roadmap에 옮겨 적었다. 기획실은 이 상태로 직접 옮기지 않고, PM 기록을 보고 표시만 바꾼다 | PM |
| **보류** | 좋지만 지금 원칙·일정·기술로는 안 된다. 다시 꺼낼 조건을 한 줄 적는다 | 기획실 또는 PM |
| **버림** | 원칙을 구조적으로 어기거나, 같은 효과를 더 싸게 내는 카드가 있다. 버린 까닭을 한 줄 남긴다(지우지 않는다) | 기획실 |

- 상태를 바꿀 때 카드의 `상태` 줄을 `검토 (2회차)`처럼 회차와 함께 바꾸고, 회차 기록에도 적는다.
- **1.0 후보와 1.x 후보 나누기**: 채택 후보마다 `넣을 때` 줄을 둔다. 판단 기준은 ① JS·데이터만이면 OTA로 늦게 넣어도 되는가(15밤 이후 콘텐츠는 첫 코호트가 닿기 전에 넣으면 된다) ② `rollout-plan.md` 3-3 처리량 점검을 해치지 않는가 ③ 네이티브 변경이 있으면 빌드 2(12-19) 동결 전이어야 한다.

## 6. 하지 않는 것

- 코드·DECISIONS·로드맵·정본 문서를 고치지 않는다. 커밋하지 않는다(필요하면 PM에게 넘긴다).
- 경쟁작의 동사를 그대로 가져오지 않는다(옷 입히기·방 꾸미기·가챠·출석 보상·에너지·친구 방문 랭킹). 참고했다면 카드에 출처를 쓰고 "무엇이 다른가"를 한 줄 쓴다.
- 오너에게 직접 묻지 않는다. 오너 판단이 필요한 것은 회차 기록의 '넘길 질문'에 적고 PM이 모아 묻는다.
