# 회의 실험 (2026-11-25, 의장 P-LEAD)

## 실험 A — 낱말 누적 → Gemini 꿈 그림 (실패: 크레딧 소진 402, **충전 뒤 실행할 실험**)

- 스크립트: `dream-compose.mjs` (키는 `.env.local`의 `GEMINI_API_KEY` 한 줄만 스크립트 안에서 읽음, 로그에 남기지 않음)
- 시도: 1회(첫 호출 probe). 결과: `HTTP 402 RESOURCE_EXHAUSTED — prepayment credits are depleted` (`log.txt`). 첫 호출 실패 시 바로 멈추게 짜서 나머지 4장은 부르지 않았다.
- 설계(충전 뒤 그대로 실행):
  | 장 | 입력 | 보려는 것 |
  |---|---|---|
  | n1-joy | 1밤 '기쁨' + 몽망이 참조 그림(`ref-mong.png`) | 캐릭터 유지(흰 눈 둘·빗 세 가닥), 글자 섞임 여부 |
  | n2-joy-popcorn | 1밤 + 2밤 '팝콘' | 앞 장 요소가 이어지는가(누적감) |
  | n3-joy-popcorn-rain-meal | + 3밤 '비' + 돌봄(밥 먹은 날) | 요소 4개에서 구도가 무너지는가 |
  | n3-repeat | n3 같은 프롬프트 다시 | 같은 입력 → 얼마나 다른가(D-13 결정성) |
  | chain-festival | 기쁨 + 팝콘 → '축제'(조합표 결과 가정) | A+B=C 결과 그림의 재미 |
- 모델 `gemini-3.1-flash-image`, 4:5, 5장. 비용은 입장문 2(테크·아트) 단가표 기준 소액.
- 판정 기준(충전 뒤): ① 5장 모두 캐릭터가 같은 아이로 보임(사람 3명 중 3명) ② 글자·낙관 섞임 0 ③ n3 대 n3-repeat 차이를 '같은 꿈'으로 보는 사람 ≥ 2/3 ④ 요소 4개에서도 64pt 썸네일에서 무엇이 있는지 셋 이상 말할 수 있음.

## 실험 B — 미리 만든 조각의 결정적 겹치기 (비용 0, 실행함)

- 파일: `collage.html` → `collage-3nights.png` (헤드리스 Chrome 캡처)
- 재료: C14b용으로 이미 뽑아 둔 Gemini 사물 조각(`docs/creative/c14b-ref/umbrella-o1·kite-o3·boat-o1·teacup-o1.jpg`) + 앱 화면에서 잘라 낸 몽망이(`ref-mong.png`). 자리 규칙: 1밤 = 위 가운데, 2밤 = 왼쪽 위, 3밤 = 오른쪽, 돌봄 = 아래 작은 자리, 몽망이 = 맨 아래에서 잠.
- 본 것(의장 관찰, 사람 판정 전):
  1. **조각 하나하나는 좋다**. 붓맛·농담이 C14b 3차 리뷰에서 통과한 수준 그대로이고, 세트 통일감은 저절로 지켜진다(같은 프롬프트 계열에서 뽑았으므로).
  2. **그러나 '한 장의 꿈'이 아니라 '종이 위 스티커 모음'으로 읽힌다.** 조각끼리 관계(비가 배 위로 내림, 연이 우산 바람에 날림)가 없다. 오너가 말한 '조합되는 꿈'의 재미는 **관계**에서 나온다.
  3. 바탕 한지 색이 조각마다 달라 그대로 겹치면 네모가 보인다 → 조각은 **바탕 없는 알파 PNG**로 손질해야 한다(곱하기 + 밝기 보정으로 임시 해결, 연한 농담이 날아감: 찻잔).
  4. 몽망이 크기·자리가 고정이라 매일 같은 그림처럼 보일 위험 → 몽망이 '꿈속 자세'(타기·안기·숨기)가 조각마다 있어야 한다.
- 결론: 결정적 조합은 **비용·일관성·안전은 이기고, 장면성은 진다.** 장면성을 메우는 길은 ① 조각 사이 '관계 규칙'(비 → 아래 사물에 빗줄기, 바람 → 가벼운 사물 기울임 등)을 문법으로 만들기 ② 자주 나오는 둘씩 조합을 미리 그린 '짝 장면'으로 두기 ③ 서버 생성은 이레 마지막 한 장(특별한 꿈)에만 쓰기. 회의록 README 결론 참조.
