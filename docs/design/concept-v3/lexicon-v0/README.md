## 2. 형식 (스키마 요약)

```json
{
  "lexVer": "0.1.0", "lang": "ko", "sensesVer": "0.1.0", "lengthLimit": 6,
  "entries": [
    { "id": "ko.0069", "lemma": "짜증", "forms": ["짜증나", "짜증남", "짱나", "ㅉㅈ"],
      "sense": "spiky.out.irritated", "intensity": 2, "flags": [], "pos": "noun",
      "source": "hand-v0", "review": { "status": "draft", "by": [] } }
  ]
}
```

- `forms`에는 **정규화한 뒤의 모습**을 적는다. 띄어쓰기를 빼고, 영어는 소문자로 적는다. 대조기는 입력도 같은 방식으로 정규화하므로, 한 자리에서 두 번 정규화할 일이 없다.
- `intensity`는 내부 값이다. 몸짓 진폭에만 쓰고 누적에는 넣지 않는다(heart-grain 2-1).
- `flags`
  - `profane`: 욕설. 결은 그대로 받는다. 공유에서 '쓴 말 보이기'를 켜도 글자는 가린다.
  - `crisis_strong` / `crisis_soft`: 위기 신호 두 단계(heart-grain 8절). 이 표시가 붙으면 `sense`는 반드시 `x.crisis`다(스키마가 강제).
  - `homonym`: 동음이의어. 한 마디로 썼을 때 가장 흔한 뜻으로 정했다.
  - `hyperbole`: 과장 표현이라 위기가 아니다.
  - `silly`: 장난 말(똥·방구 → 웃음).
  - `muted`: 가림. 운영 파일에서만 쓰고 표본에는 없다.
- `id`는 한 번 주면 다시 쓰지 않는다. 지운 항목의 번호는 비워 둔다.
- **버전과 결정성(D-13)**: 세이브의 `word`에 `{ sense, intensity, lexVer, source }`를 저장한다. 사전이 바뀌어도 **지난 말을 다시 해석하지 않는다.** 결을 바꾸는 수정은 minor 이상으로 버전을 올리고, 표면형만 더하는 수정은 patch로 올린다.

## 3. 정규화 규칙

| # | 규칙 | 예 |
|---|---|---|
| 3-1 | 유니코드 NFC로 바꾼다. 손글씨 인식 결과의 자모 분리 문제도 여기서 정리한다 | `ㅎㅏㄴ` 같은 분리형은 인식기 옵션으로 막는다 [확인 필요: ML Kit 출력 형태] |
| 3-2 | **띄어쓰기**를 모두 지운다. 한 마디가 6자 이하이므로 띄어 쓴 말은 붙여 쓴 말과 같다고 본다 | `짜증 나` = `짜증나`, `죽고 싶어` = `죽고싶어` |
| 3-3 | 문장부호와 꾸밈 기호(. , ! ? ~ … · 따옴표 괄호 등)를 지운다. 단 **이모티콘 토큰**(`:(` `<3` `^^` `-_-` 등)은 지우기 전에 먼저 떼어서 본다 | `happy!!` → `happy`, `<3` → 다정 |
| 3-4 | **동음이의어**는 '한 마디로만 썼을 때 가장 흔한 뜻' 하나로 정하고 `homonym` 표시를 단다. 먹·한지 세계와 맞는 뜻이 비슷하게 흔하면 그쪽을 고른다(차 = 茶) | 눈 = 雪, 밤 = 夜, 해 = 太陽, 새 = 鳥, 일 = work, 사과 = 과일 |
| 3-5 | **반복 접기**: 같은 글자가 3번 이상 이어지면 2개로 접고, 그래도 안 맞으면 1개로 접는다. 원래 5번 이상 이어졌으면 강도를 +1 한다 | `ㅋㅋㅋㅋㅋ` → `ㅋㅋ` 강도 2, `loooool` → `lol`, `hiii` → `hi` |
| 3-6 | **강조·약화 접두**: 강조(개·존나·완전·진짜·너무·핵·킹·왕·찐·넘 / so·very·super·really·too)를 떼면 강도 +1, 약화(좀·조금·약간·살짝 / kinda·a bit)를 떼면 −1. 범위는 1~3 | `개짜증나` → 짜증 3, `좀슬퍼` → 슬픔 1 |
| 3-7 | **굳은 신조어는 접두를 떼지 않는다.** 표면형으로 따로 적는다 | `킹받네`(= 열받다), `개꿀` |
| 3-8 | **끝 자모 꼬리**(ㅋ·ㅎ·ㅠ·ㅜ·ㄷ가 이어진 것)를 떼어 앞말로 판정한다. 꼬리는 기록만 하고 결은 바꾸지 않는다 | `배고파ㅠㅠ` → 밥, `짜증나ㅋㅋ` → 짜증 |
| 3-9 | **어미 벗기기**(최대 2번, 긴 것부터): 했어요·했어·해요·하다·이야·이다·해·요·다·어·아·야·네·지·음·함·당·잉·용 / 영어 ing·ed·es·s·y·ly(줄기 3자 이상) | v0은 활용형을 대부분 `forms`에 직접 적었다. 어미 규칙은 안전망이다 |
| 3-10 | **자모·초성 말**은 표제어로 둔다(ㅋㅋ·ㅠㅠ·ㄱㅅ·ㅊㅋ·ㅅㅂ). 초성이 두 말과 겹치면 더 안전한 쪽으로 정한다 | `ㅈㅅ`(죄송/자살) → 안전 soft |
| 3-11 | **오타·소리 나는 대로 쓴 말**은 흔한 것만 표면형에 넣는다. 편집 거리 같은 퍼지 대조는 **하지 않는다**(뜻이 엉뚱하게 바뀌어 결정성을 깨기 쉽다) | `조아`, `힘드러`, `귀차나`, `hapy` |
| 3-12 | 영어는 아포스트로피를 지운 모양으로 적는다 | `can't wait` → `cantwait` |

## 4. 대조 순서 (`rules-v0.json` `order`)

1. 정규화(3-1~3-3)
2. **위기 줄기 부분 일치** → `x.crisis` strong. 다른 어떤 규칙보다 먼저 본다. 꼬리·접두가 붙어도 약해지지 않는다
3. 이름 일치(기본 이름 표 + 세이브의 유저 이름) → `x.call`
4. 가림 목록 완전 일치 → `x.unknown` + `muted`
5. 표면형 완전 일치
6. 반복 접기(3-5) 뒤 다시 5
7. 강조·약화 접두(3-6) 뒤 다시 5
8. 끝 자모 꼬리(3-8) 뒤 다시 5
9. 어미 벗기기(3-9) 뒤 다시 5
10. 이모티콘 표
11. 다른 언어 사전 표면형 일치(한국어 속 `JMT` 등)
12. 과장 꼬리: `(상태어)+죽겠-`이면 앞말의 결을 강도 3으로 받고 `hyperbole`을 단다. 앞말이 위기 결이면 적용하지 않는다
13. **두 말 합성 분할**: 앞에서부터 모든 자리를 나눠 보고, 앞·뒤가 모두 사전에 있으면 받는다. **마음 가족 쪽을 주 결로**, 다른 쪽은 `secondary`로 둔다. `secondary`는 꿈 가중 ×2에만 쓰고 마음 벡터에는 넣지 않는다. 둘 다 같은 종류면 뒷말(서술어)을 주 결로 한다. 분할로는 위기 결을 만들지 않는다
14. 모두 실패하면 → `x.unknown`(모르는 말, 몽망이가 갸웃)

- **사전 밖 낱말 처리 원칙**: '가장 가까운 결'을 억지로 고르지 않는다. 비슷한 결을 지어내면 유저는 "내 말을 엉뚱하게 알아들었다"고 느끼는데, 이것이 '모르는 말'보다 더 나쁘다. 모르는 말에는 갸웃 + 천천히 마시기로 대답한다(heart-grain 7절).
- 1.x 서버 해석(동의 뒤)은 14번 자리에만 들어간다. 사전 안의 말은 서버로 보내지 않는다.
- 사전 밖 비율 목표: 실제 유저가 쓴 한 마디의 **85% 이상이 5~13단계에서 맞는 것** [추정]. 소프트런칭에서 집계할 수 없다(말을 서버로 보내지 않음). 그래서 종이 프로토타입과 사내 사용 기록으로 추정한다.

## 5. 욕설·금칙어·가림

| 종류 | 처리 | 결 | 공유 |
|---|---|---|---|
| 욕설(씨발·ㅅㅂ·미친·fuck·damn 등) | `profane`. 검열하지 않는다 | 뾰족(화·짜증) | '쓴 말 보이기'를 켜도 그 글자는 가린다(먹 자국만). B5 금칙어 필터와 같은 목록 형식을 쓴다 |
| 혐오 표현·성적 표현 | `muted`. **결을 주지 않고** 모르는 말과 똑같이 대답한다. 경고·판단 문구는 없다 | `x.unknown` | 언제나 가린다 |
| 다른 사람을 겨눈 말(죽을래·kys) | 안전 soft. 자기를 향한 말일 수도 있기 때문이다 | `x.crisis` soft | 공유되지 않는다 |
| 이름 금칙어 | 이 사전과 별개다(B5 `name-blocklist`) | — | — |

- 가림 목록과 금칙어 원문은 **저장소에 두지 않는다.** 운영 파일로 두고(B5와 같은 로더 형식: 한 줄에 한 항목, `=`는 전체 일치, `#`은 주석), 앱 번들에는 해시로만 넣는 안을 검토한다 [확인 필요: 6자 이하 해시는 되돌릴 수 있어 보호 효과가 약하다. 목적은 저장소 열람자 노출을 줄이는 것뿐이다].
