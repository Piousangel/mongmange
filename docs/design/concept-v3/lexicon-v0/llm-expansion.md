# 사전 넓히기 — LLM 프롬프트 설계와 검수 기준 (호출하지 않음)

- 작성: PL-2(작가) + PL-1, 2026-11-24. **설계 문서일 뿐이다.** 외부 AI는 호출하지 않았다. 실제 호출은 오너가 승인하고 PM이 키를 준비한 뒤 한다(컨셉 리뷰 8절 ③).
- 위치: D-02·D-26의 'LLM = 출시 전 제작 도구' 줄. 결과는 사전 파일로 고정하고, 사람이 본 항목만 출시한다. 런타임 호출은 0이다.

## 0. 모델과 비용 [가격 확인 필요]

| 쓰임 | 모델 id | 가격(입력/출력, $/1M 토큰) | 까닭 |
|---|---|---|---|
| 프롬프트 A: 활용형·후보 생성 | `claude-opus-5-5` | $4 / $20 | 한국어 구어·신조어 품질이 가장 중요하다. 양이 적어 비용 차이가 작다 |
| 프롬프트 B: 눈가림 판정(두 번째 의견) | `claude-sonnet-5-5` | $2 / $10 | A와 **다른 모델**로 판정해야 같은 편향이 겹치지 않는다 |
| (참고) 1.x 런타임 해석 실험 | `claude-haiku-5-5` | $0.10 / $0.50 | 컨셉 리뷰 4-2. 이번 범위 밖 |

- 가격은 claude-api 스킬 모델 표(2026-11-03 캐시) 기준이다. 실행 전에 Anthropic 가격 페이지에서 다시 확인한다.
- 보내는 방식: **Message Batches**(비동기, 표준가의 50%)와 **프롬프트 캐싱**(결 48 정의를 시스템 맨 앞에 고정해 둠)을 쓴다. 출력은 구조화 출력(`output_config.format`, JSON 스키마)으로 받는다. Opus 5.5·Sonnet 5.5는 강제 `tool_choice`(any/tool)를 쓰면 400이 나므로 쓰지 않는다. Opus 5.5는 생각(thinking)을 끌 수 없으니 `effort`를 `medium`으로 둔다.
- 비용 추정 [추정, 리뷰 M5 반영]: 5천 표제어를 요청당 20개씩 묶으면 250건이다. 건마다 새 입력 약 1천 토큰 + 캐시 읽기 약 5천 토큰 + 출력 약 3천 토큰이면 정가 약 $16, 배치로 약 $8이다. 여기에 **생각(thinking) 토큰**이 붙는다. Opus 5.5는 생각을 끌 수 없고 생각 토큰은 출력 요금이다. 요청당 1~3천 토큰이면 정가 $5~15가 더해진다. 그 밖에 새 표제어 후보 요청(결 48 × 2언어), 프롬프트 B 눈가림 판정, 위기 시험 입력 생성(4절)이 더해진다. **합계는 $30~50 안팎**이다. rollout-plan 5절 오너 할 일 3번의 "예상 수 달러"도 이 값으로 고쳤다.
- 거절 처리: 위기 관련 항목은 안전 분류기가 `stop_reason: "refusal"`로 거절할 수 있다. 응답을 읽기 전에 늘 `stop_reason`을 확인한다. 거절된 묶음은 **사람(전문가) 큐로 보낸다.** 다른 모델로 우회하지 않는다.
- **서버 쪽 `fallbacks`는 일부러 끈다.** claude-api 스킬의 기본값은 Opus 5.5에서 `fallbacks: "default"`를 켜는 것이다. 하지만 거절된 위기 항목이 다른 모델로 조용히 넘어가면 사람 검수를 건너뛰게 된다. 구현자가 기본값대로 켜지 않도록 여기 적어 둔다.
- 데이터: 입력은 팀이 쓴 표제어와 결 정의뿐이다. **유저 데이터는 0**이다(출시 전이고 유저 글은 기기 밖으로 나가지 않는다).

## 1. 공통 시스템 프롬프트 (캐시 대상, 고정)

```
너는 몽망이 키우기(먹 한 방울을 키우는 모바일 게임)의 어휘 편집자다.
유저는 날마다 붓으로 낱말 하나(한국어 6글자 이하, 영어 한 단어)를 쓴다.
게임은 그 낱말을 아래 '말결' 목록 중 하나로 읽고, 몽망이가 몸짓으로 대답한다.
목적: 이 목록은 낱말에 맞는 몸짓을 고르고, 위기 신호를 놓치지 않고 도움 받을 곳을 안내하기 위한 것이다.

[말결 목록] — senses.json의 id · 이름 · 한 줄 정의 · 대표 예 3개를 그대로 붙인다(51줄)
[특수 대답] x.call(이름) · x.unknown(모름) · x.stay(곁 대답: 자해·자살 암시, strong/soft)

원칙
- 목록 밖 id를 만들지 않는다. 맞는 것이 없으면 "x.unknown".
- 한 낱말에 결은 하나다. 두 결 사이에서 망설이면 confidence를 low로 적고, 대안을 alt에 하나만 적는다.
- 위기 신호는 놓치지 않는 쪽으로 판단한다. 과장 관용구('배고파 죽겠다')는 위기가 아니다.
- 실제로 쓰이는 형태만 적는다. 지어낸 신조어·띄어쓰기 변형·형태소를 늘어놓지 않는다.
- 혐오·성적 표현과 장애·성별·지역 비하어는 형태를 적지 말고 muted=true로만 표시한다.
- 자해·자살의 수단·방법·장소를 새로 적지 않는다(자살예방 보도준칙 4.0의 '방법 미보도' 원칙과 같은 선).
- 사람 이름을 표제어나 형태로 적지 않는다.
- 설명 문장을 쓰지 않는다. 스키마에 맞는 JSON만 낸다.
```

## 2. 프롬프트 A — 표제어 → 활용형·결 후보 (`claude-opus-5-5`)

입력(사용자 메시지)은 사람이 먼저 적은 표제어 20개와, 그 표제어를 고른 결 id(사람의 가설)다.

```
아래 표제어마다:
1) forms: 흔한 활용형·줄임·구어·소리 나는 대로 쓴 형태·초성 형태를 최대 8개.
   띄어쓰기 없이, 영어는 소문자·아포스트로피 없이. 길이 상한(ko 6자 / en 15자)을 넘는 것은 빼라.
2) sense: 가장 맞는 결 id 하나. 사람 가설(hypothesis)과 다르면 그렇게 적고 disagree=true.
3) intensity: 1~3 (1 = 약함·일상, 2 = 보통, 3 = 강조·과장).
4) flags: profane / homonym / hyperbole / silly / crisis_strong / crisis_soft / muted 중 해당하는 것.
5) confidence: high / low. low이면 alt에 두 번째 결 하나.
표제어: [{ "lemma": "짜증", "hypothesis": "spiky.out.irritated" }, …]
```

출력 스키마(구조화 출력, `strict`):

```json
{ "type": "object", "additionalProperties": false, "required": ["items"],
  "properties": { "items": { "type": "array", "items": {
    "type": "object", "additionalProperties": false,
    "required": ["lemma", "forms", "sense", "intensity", "flags", "confidence", "disagree"],
    "properties": {
      "lemma": { "type": "string" },
      "forms": { "type": "array", "items": { "type": "string" }, "maxItems": 8 },
      "sense": { "enum": ["bright.in.joy", "… 48 + x.call · x.unknown · x.stay"] },
      "alt": { "enum": ["…같은 목록…"] },
      "intensity": { "enum": [1, 2, 3] },
      "flags": { "type": "array", "items": { "enum": ["profane", "homonym", "hyperbole", "silly", "crisis_strong", "crisis_soft", "muted"] } },
      "confidence": { "enum": ["high", "low"] },
      "disagree": { "type": "boolean" } } } } } }
```

- 새 표제어 후보: 결마다 한 번, "이 결에 흔히 쓰는 한 마디 30개(사람 목록에 없는 것)"를 따로 요청한다. 같은 스키마에서 `hypothesis` 없이 받는다. **후보는 모두 사람이 고른다.**

## 3. 프롬프트 B — 눈가림 판정 (`claude-sonnet-5-5`)

- A의 결과를 보여 주지 **않는다.** 표면형(활용형 하나를 무작위로 고름)만 주고 결 id를 고르게 한다. 강도·위기 여부도 함께 받는다.
- 일치율을 보는 용도다. A ↔ B가 다른 항목은 사람 검수 큐 맨 앞으로 보낸다.

```
아래 낱말을 쓴 사람에게 몽망이가 대답한다. 각 낱말의 결 id 하나, 강도, 위기 여부를 골라라.
낱말: ["짱나", "설레임", "비가와", …]
```

## 4. 위기 묶음은 다르게 만든다

1. **사람(전문가 또는 상담 기관 자료)이 줄기 목록을 먼저 만든다.** LLM이 위기 표현을 새로 지어내게 하지 않는다.
2. LLM에게는 그 줄기의 **표기 변형**(띄어쓰기·초성·오타·구어)만 요청한다. 거절이 나오면 사람 큐로 보낸다.
3. 판정은 반대로 한다. 사전 전체(5천)를 프롬프트 B로 "위기 신호가 있는가"만 다시 훑게 해서, 위기 묶음 밖에 있는 위기 후보를 찾는다.
3-1. **놓침은 사전 밖에서 생긴다**(리뷰 C1·M5). 그래서 프롬프트 B를 **시험 입력 만들기**에도 쓴다: "10대 구어·소리 나는 대로 쓴 꼴·알고리즘 회피어·초성·끼운 글자로 쓴 위기 표현의 시험 입력"을 만든다(사전 항목이 아니다. 수단·방법은 새로 쓰지 않는다). 전문가 승인 뒤 `crisis-test-v0.json`의 **보류 세트**로 넣고, 대조기에 돌려 놓침을 센다. 기준은 strong·soft 놓침 0이다.
4. 최종 승인은 전문가 1명 + PL-2다. **놓침 0**이 기준이다. 전문가를 **누가, 언제** 섭외하는지는 PM이 V0-3·V5c 일정에 이름 칸을 만든다.

## 5. 검수 기준 (사람)

| 항목 | 통과 | 떨어짐 |
|---|---|---|
| 결 id | 검수자 둘이 따로 매겨 같으면 `agreed` | 다르면 `disputed` → PL-1이 결 정의를 고치거나 한쪽으로 정하고, 까닭을 `review.notes`에 남김 |
| 활용형 | 실제 쓰임을 한 사람 이상이 확인(검색 또는 본인 사용) | 지어낸 꼴, 다른 뜻과 겹치는 꼴(예: '배'를 '배고파'에 넣기), 길이 초과 |
| 동음이의 | `homonym` 표시 + 3-4 규칙에 맞는 기본 뜻 | 표시 없이 뜻이 둘 |
| 강도 | 표제어 기준 1~3, 같은 결 안에서 순서가 말이 됨(짜증 2 < 개짜증 3) | 감정 크기를 사람 평가처럼 매김(예: '우울' 3) — 강도는 말의 세기이지 사람 상태가 아니다 |
| 욕설·가림 | 욕설은 `profane`, 혐오·성적 표현은 `muted`(형태는 운영 파일에만) | 저장소 파일에 혐오 표현 원문이 들어감 |
| 위기 | 전문가 승인, 놓침 0 | LLM만 보고 넣거나 뺌 |
| 출처 | `source: llm` 또는 `llm+edit`, `review.notes`에 모델 id·프롬프트 버전·배치 id | 출처 없음 |
| 표본 감사 | `agreed` 항목에서 무작위 5%를 셋째 사람이 다시 보고, 오류율 ≤ 3% | 3% 넘으면 그 결 전체를 다시 검수 |

- 목표 수치: 검수자 둘 일치 ≥ 85%, 모델(A) ↔ 사람 일치 ≥ 80%, 모델(A) ↔ 모델(B) 일치 ≥ 80%, 위기 놓침 0. 이것은 컨셉 리뷰 8절 ③의 통과 기준과 같다.
- 사람 공수 [추정]: 5천 항목 × 2명 × 항목당 약 10초 ≈ 28시간. 쪼개서 결마다 PL-2 + 원어민 1명(영어)이 맡는다.
