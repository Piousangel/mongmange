# '무슨 말을 썼나' 블라인드 — 자극물 만들기와 합격 기준 (검증 ④)

- 작성: PL-1, 2026-11-24. 제작은 아트 + 모션 팀, 모집은 오너 또는 PM이 맡는다.
- 묻는 것: **같은 사람이 서로 다른 낱말로 키운 몽망이를 보고, 남이 그 낱말을 맞힐 수 있나?** 맞힐 수 있으면 "말이 몸에 반영된다"는 증거다. 우연보다 못하면 결은 '숨은 값'일 뿐이고, 오너가 지적한 "반영되는 것 같지 않다"가 그대로 되풀이된다.
- 컨셉 리뷰 8절 ④(3초 몸짓 녹화, 4지선다)를 두 갈래로 나눈다. **S1 정지 그림**(이레 뒤 몸, 이 과제의 주 시험)과 **S2 3초 몸짓**(선택)이다.

## 1. 자극 설계 (S1)

| 세트 | 같은 '사람'(고정) | 낱말 3개(가족이 모두 다름) |
|---|---|---|
| A | 씨앗 1 · 송연먹 · 손 획 시드 1 | 짜증(뾰족) · 비(자연) · 사랑해(포근) |
| B | 씨앗 2 · 유연먹 · 손 획 시드 2 | 졸려(포근) · 시험(나날) · 바다(자연) |
| C | 씨앗 3 · 자연먹 · 손 획 시드 3 | ㅋㅋ(들뜸) · 엄마(곁) · 슬퍼(가라앉음) |
| D | 씨앗 4 · 송화먹 · 손 획 시드 4 | 귤(살림) · 무서워(뾰족) · 별(자연) |
| N(통제) | 씨앗 5 · 송연먹 · 손 획 시드 5 | 짜증 · 비 · 사랑해. 단 **세 그림 모두 편집하지 않은 같은 몸**이다 |

- 그림 한 장 = 첫 이레(7밤)를 마친 아침의 몸이다. 7밤 중 **5밤은 그 낱말**이고, 2밤은 '모르는 말'(가족에 세지 않음)이다. 그래서 heart-grain 5-2 규칙상 그 낱말 가족의 이레 흔적 **하나만** 몸에 스민다. 같은 세트의 세 그림은 **가족 흔적만 다르고** 나머지(체형·빗 모양·먹·손 획·포즈)는 똑같다.
- 세트 N은 '그럴듯한 오답' 통제다. 아무 차이가 없는데도 우연(33%)보다 훨씬 잘 맞히면, 파일 이름·순서·압축 흔적 같은 **새는 단서**가 있다는 뜻이다. 그러면 시험 전체를 무효로 한다.

## 2. 지금 렌더로 근사하는 방법

지금 렌더는 이레 흔적(마음 가족)을 그리지 못한다. 그래서 **몸은 실제 렌더로 캡처하고, 흔적만 정해진 수치로 편집해** 근사한다. 코드는 바꾸지 않는다.

| 단계 | 방법 | 비고 |
|---|---|---|
| ① 바탕 캡처 | 웹 렌더(`pnpm web`)의 M1 보드(`?screen=m1`, `apps/mobile/src/screens/M1Board.tsx`)가 쓰는 것과 같은 조합으로 그린다: 타고남 `traitsOf(seed)` + 먹 + `handRecords(seed, 7, shape)`(`packages/core/src/visual/pose.ts`). 세트마다 1장을 2배 해상도, 낮 화면, 빈 한지 배경으로 캡처한다. 캡처 방식은 `scripts/m1-capture.mjs`와 같다(playwright) | 지금 M1 보드는 시드 1~12 칸을 늘어놓는다. 칸 하나를 잘라 쓰거나, 테크 리드가 `?seed=` 단독 보기를 다는 것은 이번 범위 밖이다 [확인 필요] |
| ② 세 장 복제 | 같은 바탕을 3장으로 복제한다(세트 N은 그대로 둔다) | |
| ③ 흔적 편집 | 아래 표의 **수치만** Figma(벡터 위에 덮기) 또는 이미지 편집기로 적용한다. 편집 기록을 표로 남긴다 | 편집자는 낱말을 모르는 사람이 좋다. 가족 id만 받는다 |
| ④ 내보내기 | 세 장 모두 같은 크기·같은 압축(PNG 무손실)으로 낸다. 파일 이름은 무작위 4자로 한다 | 새는 단서를 막기 위해서다 |
| ⑤ 썸네일판 | 같은 그림을 96px로 줄인 판도 만든다(D-24 작은 크기 정체성) | 보조 지표 |

**가족 흔적 편집 수치**(heart-grain 3절 '이레 흔적'을 숫자로 옮김. W = 몸 폭)

| 가족 | 편집 |
|---|---|
| 들뜸 | 빗 세 가닥을 위로 +6°. 번짐 고리 바깥 가장자리에 고리 색 잔방울 6~8개(지름 0.02W, 고르게 흩음) |
| 포근 | 번짐 고리 폭 ×1.25, 고리 가장자리 블러 +2px(2배 해상도 기준) |
| 뾰족 | 빗 끝을 둥근 끝 → 45° 사선으로 자른 각진 끝(방필). 번짐 고리 블러 −50%(경계가 또렷하게) |
| 가라앉음 | 번짐 고리 폭 ×1.2 + 블러 +3px. 몸 가장자리 안쪽에 폭 0.03W의 '물기 윤' 띠(몸 색에서 종이 쪽으로 10%). 빗 −8°(늘어뜨림, 처짐 아님) |
| 자연 | 번짐 고리를 오른쪽 위 방향으로만 ×1.3 늘림(바람 결) |
| 살림 | 몸 폭:높이 +0.03(더 동글게), 바닥 받침 띠 폭 ×1.3 |
| 곁 | 빗 바깥 두 가닥을 가운데 쪽으로 3°씩 모음. 몸 전체를 화면 앞(아래)쪽으로 4° 기울임 |
| 나날 | 빗 세 가닥의 각도 차를 0으로(곧게 나란히), 몸 높이 +2% |

- **하지 않는 것**: 소품·아이콘·글자·눈물·하트·빗방울 같은 새 그림 요소, 먹 색상(색조) 바꾸기, 표정 바꾸기. 이레 흔적은 실제 게임에서도 이 채널만 쓰기로 했다(heart-grain 4절 아래 메모). 이 규칙을 어기면 '실제 게임보다 쉬운 시험'이 된다.

### S2(선택): 3초 몸짓 클립

- 같은 바탕 몸 위에서 heart-grain 4절 표의 '3초 대답'을 모션 팀이 키프레임으로 만든다(Figma Smart Animate 또는 After Effects). 길이 3초, 소리 없음, 반복 없음.
- 컨셉 리뷰 8절 ④ 그대로 **낱말 4개 × 2세트 = 8클립**, 4지선다다. 합격은 정답률 ≥ 50%(우연 25%)다.

## 3. 진행

| 항목 | 내용 |
|---|---|
| 참가자 | 외부 **10명**. 종이 프로토타입 테스터 5명은 빼야 한다(결 카드를 이미 봤다). 앱을 모르는 사람, 만 14세 이상(온라인 설문이라 이름·연락처는 받지 않음) |
| 형식 | 온라인 설문 한 개(Google Forms 등), 약 8분 |
| 순서 | ① **몸만**: 세트 5개(A·B·C·D·N)를 무작위 순서로 보여 준다. 세트 안에서도 그림 순서를 섞는다. 그림 3장과 낱말 3개를 함께 보여 주고, **그림마다 낱말 하나를 고르게 한다**(같은 낱말을 다시 골라도 된다. 그래야 문항끼리 독립이다). 확신(상/하)과 "무엇을 보고 골랐나" 한 줄도 받는다 ② **몸 + 꿈 카드**: 같은 그림에 그날 꿈 카드(결의 첫 모티프, 지금 꿈 카드 렌더로 캡처)를 곁들여 다시 묻는다. ③ **썸네일**(96px)로 ①을 다시 한다 |
| 왜 ①을 먼저 하나 | 꿈 카드(비 → 빗소리)는 너무 쉬운 단서다. 몸만으로 맞히는지를 먼저 깨끗하게 재야 한다 |

## 4. 합격 기준 (S1, 몸만)

| 지표 | 합격 | 근거 |
|---|---|---|
| 전체 정답률(세트 A~D, 10명 × 12문항 = 120) | **≥ 50%(60개 이상)** | 우연 33%. 문항이 독립이라고 보면 60/120의 유의확률 p ≈ 0.0001이다. 같은 사람의 답끼리 묶이는 효과를 생각해 아래 사람 단위 기준도 함께 본다 |
| 사람 단위 | 10명 중 **7명 이상**이 12문항 중 5개 이상 맞힘 | 소수의 '눈 좋은 사람'이 평균을 끌어올리는 것을 막는다 |
| 세트별 | 세트마다 **≥ 40%**(30문항 중 12개 이상) | 특정 가족 조합만 구별되는 것을 막는다 |
| 통제 세트 N | 정답률 **≤ 45%** | 넘으면 단서가 샌 것이다 → 시험 무효, 다시 만든다 |
| 보조: 몸 + 꿈 카드 | 기록만 한다(기준 없음) | 몸만 떨어지고 꿈 카드로만 붙으면 "꿈이 일을 다 하고 몸은 반영이 약하다" → 이레 흔적을 강화한다 |
| 보조: 96px 썸네일 | 기록만 한다. 몸만 기준의 −10%p 안쪽이면 양호 | D-24 |
| "무엇을 보고 골랐나" 감사 | 편집 표에 없는 단서(색·파일 순서 등)를 말한 답이 10% 이상이면 재검토 | 새는 단서 점검 |

- 판정: 위 다섯 기준(전체·사람·세트·통제·감사)을 모두 통과하면 **④ 통과**다. 컨셉 리뷰 8절은 ①·④가 통과하면 C′로 결정한다고 했다.
- 떨어지면 무엇을 고치나: 가족별 오답 행렬(어느 가족을 어느 가족으로 착각했나)을 만들어, 서로 헷갈린 두 가족의 흔적 편집 수치를 벌린다. 다시 시험하는 데 하루가 걸린다.

## 5. 한계

- **근사다.** 실제 렌더(셰이더 번짐·움직이는 숨)는 손 편집보다 덜 또렷하거나 더 또렷할 수 있다. 통과해도 구현 뒤 실제 렌더로 같은 시험을 한 번 더 한다(그때는 `pnpm verify`에 넣을 '시드 100개 썸네일 거리' 검사와 함께).
- 실제 유저의 7밤은 한 낱말을 5번 쓰지 않는다. 이 시험은 '결이 몸에 보이는가'의 상한을 재는 것이다. 섞인 말로 자란 아이가 구별되는지는 28밤 문양(상위 3가족) 단계에서 따로 본다.
